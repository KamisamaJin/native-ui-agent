## Group expansion and strict outcomes

Flat `assertions` each produce one platform/key outcome. In `parameterizedGroups`, inherit the group's mandatory flag, platforms, aspect, criterion, allowed evidence method, and requirement references, then produce one outcome for **each explicit member key**, using that member's concrete target and expected value. Never replace the member records with a blanket “all rows passed.” Record observed row/field IDs, evidence locators, and inaccessible reasons. No member can be inferred from a neighboring row, an unchanged source declaration, an aggregate screenshot claim, or a similar candidate.

A set-valued equality is one observed collection relationship. Keep the expected set, actual observed set, and a coverage record for each expected entry. For example, selected/native presence sets cannot be passed by inspecting only the first row; capture coverage cannot be passed after seeing only a prefix of the component. If the collection is incompletely observed, outcome is UNASSESSED. If a complete observation demonstrates a mismatch, outcome is FAIL. No unseen row is assumed absent, selected=false, covered, or readable.

A tuple such as a native origin, hit rectangle, role alternative, or exact action payload is one property with a complete required value. All value components must be supported before PASS; a partially inaccessible value makes that predicate UNASSESSED. Such a predicate is never a full-rule or whole-component pass. Row-native names with `labelIncludes` require the complete specified set of caller strings, independently of pixels. Android/Apple alternatives are platform-specific alternatives for the same property.

Report PASS, FAIL, or UNASSESSED for each applicable platform/key. A group, case/state/aspect, or public-rule rollup passes only if all its applicable mandatory predicates pass. Any FAIL makes that rollup FAIL; otherwise any UNASSESSED makes it INCOMPLETE. Never report a full rule passed when a required sub-aspect is unknown. A matrix PASS establishes the enumerated prospective matrix; it is not a claim of universal correctness over untested cross-products. The coverage ledger names deliberately sampled dimensions, and unexamined details must not be narrated as observed successes.

## Capture and native execution

Use each concrete case environment. The host offered width includes the prescribed outer margins; card width is offered width minus 32. Record native logical units and physical pixel scale. Apple categories are native equivalents of the named Android scale modes, not equal glyph ratios. Verify the actual active environment, rather than merely logging the model's requested constants.

Execute triggers sequentially on one mounted presentation slot. Whole-model replacements must update the same process/host without an app restart or implicit partial merge. SwiftUI value recreation is normal and does not violate “same mounted host.” The caller withholds echoes after actions until an explicit replacement. Each checkpoint contains the exact callback interval count and each actual typed payload. No automatic transition or estimated delay substitutes for caller control.

A full visual checkpoint requires enough parent-scroll captures to cover the whole component and its inventory. Each such checkpoint has a full visible-field inventory and explicit new/changed exact-string members. Unchanged field identities retain their initial exact-string check rather than receiving redundant independent exact-string passes at every echo. They must still appear in the actual capture-coverage record, and layout/overlap/overflow are assessed at the new visual state. Do not infer an unseen lower part from source. Scrolling to the top for origin measurements is allowed; retained scroll offset after replacement is not itself a defect.

A focused action checkpoint requests a local visible indicator/checkbox/chevron/status probe, plus native state and callback evidence. It does **not** request another complete parent-scroll capture. One viewport or a target crop with source/state provenance is sufficient when it clearly shows the required indicator. Its result is limited to the keyed local property. Native-only replacement checkpoints request no pixels and receive no new pixel PASS. Their semantic gate, selection, enabled state, structure and callback claims must still be observed actually.

For `documentedIdentifierSetEquals`, examine descendants in the documented fixed-ID and `rr.option.*`/`rr.size.*` namespace, including stale or unexpected old IDs. Ignore unrelated additional test identifiers. Set order is irrelevant; major visual flow and meaningful native read order are separate predicates. Logical pixel targets such as `header.heading`, `detail.body`, and row fields do not add test-ID requirements beyond the unchanged public brief.

A native disabled activation may be recorded as a real attempted tap/accessibility operation which the platform refuses because the target is disabled. It must show the actual target/disabled state and real zero-callback interval. An unexecuted script is not an attempt. If the native method cannot be invoked or observed, keep that stimulus/property UNASSESSED instead of manufacturing a successful activation.

## Visual rubric and representative probes

Use the unchanged brief for token values and structural expectations. The SVG is a structural reference, never a runtime image or exact golden. Accept native font/glyph metrics, native spinner/check/parcel/chevron shapes, ordinary antialiasing, and native script/bidirectional shaping. Do not require exact line breaks across platforms. All supplied text remains exact caller content; it must be readable and untruncated where the corresponding field predicate is assessed.

Inspect hierarchy, major region flow, actual text readability, selected and disabled distinctions, conditional/status structure, leading/trailing mirroring, touch geometry, parent scroll reach, and coherent light/dark color roles. Flat sampled color fills allow RGB channel delta at most 12. Use the per-predicate radius/position tolerances. The base tile may remain 52 or grow with enlarged native text. Notes panel shape refers to the full disclosure/body panel.

Shared radii/spacing/font/token values are probed at representative states instead of repeated on every row and every model. Each representative role sample is an explicit member. Dark/light financial choice, status, long-content, direction and enlarged-text coverage is distributed across the cases. The private coverage ledger explains this distribution. It does not authorize assuming that an unmeasured font or unseen palette combination passed.

## Evidence classes and unsupported methods

Every predicate has exactly the allowed evidence class in the oracle. Bind evidence to the anonymous source snapshot/build/install/run, native platform, case, checkpoint, model, actual environment, and current mounted host. A self-review or planned script cannot establish that binding.

- Rendered pixels prove actual visible ink, color, clipping, indicator, and region/layout relationships. They do not prove native semantic roles, invisible touch padding, or callbacks.
- Native bounds require actual runtime/accessibility/instrumentation geometry in logical coordinates and scroll context. A source size constant or pixel guess is insufficient. Establish actual hit bounds where a minimum touch rectangle is claimed.
- Native semantics require actual native names, identifiers, role/trait/value, enabled/selected/checked/expanded state and read order. A source accessibility modifier does not prove an actual tree.
- Callback trace requires captured actual typed actions and interval counts. Handler source, claimed assertions and screenshots are not action capture.
- Native interaction requires execution evidence for activation, native environment, scroll and same-host replacement. A source script without execution is unsupported.
- Native typography requires resolved native font/layout observations. Three sampled contexts contain nine predicates for system family, base size and native scaling. Source font declarations, visual resemblance or a successful current-runtime build cannot prove them. If the platform/tool cannot expose them, record UNASSESSED explicitly. The budget revision reduced repeated font probes; it did not make unknown font claims pass.
- Source audit applies only to the explicit API and source-only compatibility predicates. Keep iOS 14, macOS 11, guarded imports/fallbacks, Swift language mode and unchanged deployment declarations separate. A current installed iOS simulator build does not prove minimum-target compatibility, and no historic OS runtime screenshot is required.

Missing output, inaccessible inspection, an unobserved row, unsupported method, unbound artifacts, uncertain source provenance, or a hidden/unreadable portion is UNASSESSED. A directly observed contradiction is FAIL. Do not convert an actual absent required node or wrong known value into a favorable unknown. Conversely, lack of a method alone is not proof of a defect. Preserve pass/fail/unassessed counts and concrete evidence limits separately; no weighted average can hide unknown coverage.
