# Pre-evidence independent evaluation method

This preparation uses only the selected, already-frozen size-revision oracle/public artifacts and new evaluator files. No candidate source, raw runtime evidence, reviews, tool code, workspaces, assignments, prior experiments, or business outcomes have been opened. The coordinator supplied uniform activation-method limits before candidate evidence; these are recorded separately and do not specify desired outcomes.

## Scope and expansion

The expander inherits every parameterized group's aspect, criterion, method, references, mandatory flag and platforms, then creates a separate concrete row for every explicit member key. It does not count a group as one pass. The source predicates are included once per applicable platform, independently of cases.

- D0: six initial cases, 35 checkpoint contexts, 1,830 platform-expanded runtime rows plus 379 source rows = **2,209** results.
- FINAL: eight cases, 47 checkpoint contexts, 2,518 platform-expanded runtime rows plus 379 source rows = **2,897** results.
- D0 platform counts: Android 1,100; Apple 1,109.
- FINAL platform counts: Android 1,444; Apple 1,453.

Plans have no outcome fields. Preparing them is not grading. Context registries hold the concrete model, canonical model SHA256, actual requested environment, environment SHA256, trigger, preceding checkpoint and capture scope. These are private fixtures, not public task material.

The assembler cannot produce a report without at least one actual permitted raw runtime artifact. Its file reads require explicitly supplied evidence/source scopes. Results are new files under this evaluator directory; existing assessments and frozen artifacts cannot be overwritten. Every report contains exactly one row per platform/key, including unknown rows. Decisive outcomes require exact raw file paths/SHA256/locators and exact candidate/source/platform/checkpoint/model/environment binding. Unknown rows still contain the required binding and explicit missingEvidenceMethod.

## Raw evidence comes first; schemas are an indexing aid

The supplied schemas describe this reviewer's normalized evidence index and decision ledger. They are **not requirements on the native bridge's original JSON or logs**. A raw packet can use an old schema, a new schema, plain native command output, a typed callback string, or actual image files. Inspect the actual records and normalize faithfully after their paths are authorized. Preserve exact raw file references and locators; never replace raw evidence with the normalized file alone.

Do not deny adequate evidence because it lacks a newer label, diagnostics field, metadata object, fixture hash, callback wrapper, bounds spelling, or screenshot manifest key. A binding may be established by actual execution sequence, content plus run correlation, native command output, visible unique fixture text, or their combination. Record the derivation and exact sources. The requested model hash can be computed from the frozen fixture while the evidence binding is justified from actual input/execution/content; the hash need not appear in the old native output.

Conversely, do not copy the expected model into an observed-value field and call it evidence. Input/setup constants, source declarations, a planned script, an implementer self-review, and a requested activation label do not establish actual runtime behavior. If the actual observation or exact binding cannot be established, mark that predicate UNASSESSED for the concrete missing method/detail. Schema absence alone is not that detail.

Legacy callback variants may be normalized from actually captured Kotlin constructor strings, Swift associated-value strings, enum fields, payload objects, or event lists. Preserve actual count and arguments; do not fabricate default/null fields. One execution log can support separate indexed observations for callback facts, semantics, or actual activation when it actually contains those facts. Normalized records can reference different pointers/lines in the same raw file.

## Candidate and checkpoint binding

Before grading, obtain permitted anonymous source/evidence paths from root. Do not search other locations. Do not inspect reviews, tool/version assignments, strategy reports, or outcomes. Source reads are limited to the oracle's sourceAssertions: public API construction/visibility/types and source-only availability/compatibility. Do not use business handler bodies as substitutes for runtime actions or rendering.

Each decisive runtime record must bind to the anonymous source snapshot, native platform, exact case/state, model ID/hash, environment hash and current mounted host. Identical model values before and after a no-echo action require execution/interval correlation; a matching image alone does not prove the action happened. A native-only checkpoint receives no new pixel pass. A focused action image supports its local indicator/status property, not a complete scroll audit.

Never borrow a good image, callback trace or source audit from another anonymous specimen, platform, model, checkpoint or revision. Global source assertions apply only to the exact candidate source seal. A current-runtime build is not proof of an old OS runtime and does not itself establish minimum deployment compatibility.

## Visual review procedure

For each required full visual checkpoint, index the actual original native captures in parent-scroll order. Record image paths/hashes, dimensions, pixel scale when known, native viewport/scroll coordinates where available, and the fields/regions actually covered. Inspect original-size images for long text; a small contact sheet is only a navigation aid. Derived crops must retain original path/hash and crop coordinates. No generation, retouching, invented text or reconstructed screenshot is allowed.

Use the public SVG for structural intent only. It is not native runtime evidence or an exact golden. Inspect the actual supplied text, branch/status structure, selected/disabled/check states, native reflow, direction, theme colors, actual overlap/overflow and complete scroll reach. Native line metrics, script shaping and glyph shape differences are allowed by the brief.

For changed/new text members, inspect the complete string across the actual captures. A visible prefix, native AX label or source literal does not prove the final words are drawn. For capture-inventory set predicates, record the actual observed field IDs and coverage for every required inventory entry. Missing coverage prevents PASS; it is not silently inferred from another row or from the previous image. Unchanged text is not assigned a redundant new exact-string result where no such predicate exists.

For overlap predicates, credit actual screenshots and adequate actual native overlap/geometry diagnostics tied to those captures, even when their raw schema is old. Distinguish colliding meaningful ink/siblings from intended ancestor/descendant containment, transparent padding, decorative overlays and boundary touching. Do not manufacture an overlap from a text element's large AX frame alone. A directly visible occlusion or a reliably observed sibling collision is a valid counterexample; a clean layout claim needs complete relevant coverage. Do not require an absent new overlap-array metadata field when the actual pixels or older runtime data are adequate.

For flat colors, sample away from antialiasing, shadows, glyph edges and borders; apply the frozen tolerance. For geometry, retain logical-versus-physical coordinate conversion. Exact physical hit bounds cannot be inferred from image size. Typography resemblance is not a resolved-font measurement.

## Evidence method separation

- Actual native screenshots/image-derived observations establish visible pixels. Source color/font/text constants and the reference SVG do not.
- Actual native or accessibility frames can establish position, container width, origin and containment where applicable. **UIKit AX frames do not establish physical hit bounds.** MinimumTouchBounds requires actual native hit-region instrumentation, actual hit-test traces or adequate physical touch evidence. A large AX or layout rectangle alone is insufficient for either a physical-hit PASS or a physical-hit FAIL.
- Actual native tree output establishes native identifiers, roles, names, enabled/selected/checked/expanded values and read order. Source modifiers are not native tree evidence.
- Actual callback records establish count/payload facts independently of activation-method proof. Do not discard a genuine callback because the bridge used a different activation route; also do not use that callback alone to prove the requested route.
- Actual native execution establishes gestures, accessible actions, environment, scroll and same-host replacement only to the extent performed/observed.
- Resolved runtime font/layout measurements establish native family, size or scaling. **Source-only fonts do not establish runtime typography.** Unknown font methods remain explicitly unassessed.
- Anonymous source audits establish only the enumerated source-only API and minimum-target compatibility assertions. Unsupported availability claims stay unknown; do not import external docs/tool code during this task.

## Uniform pre-evidence activation limits

The coordinator reported that iOS requested accessibilityActivate routes to actual XCUI tap, with no AX performAction proof; Android invokes native semantic OnClick, with no OS physical touch; blocked_disabled means the observer declined to dispatch to the disabled control. Apply the observed mechanism, not the requested method label.

For the frozen executedNativeActivation predicate, an actual XCUI/physical tap can establish a requested tap. It does not establish AX activation. Actual current-node Android native semantic OnClick can establish native semantic activation when executed and bound to the node, but does not establish physical tap. A declined dispatch does not establish delivered native activation, though the actual empty callback interval and disabled native state remain separately assessable. If a requested mechanism was not exercised or cannot be proved, that method-coverage predicate is UNASSESSED; do not call it a component defect solely because the capture bridge lacks the method.

These limitations do not preassign any specimen outcome. Raw traces must still be inspected after paths are supplied. The classifier records a normalized observedActivationMechanism derived from the actual evidence; it does not require the old native file to contain that new key.

## Collections, counterexamples and rollups

Every explicit group member gets its own outcome/evidence/coverage row. A group/public rule cannot pass while a mandatory member is unassessed. Set-valued predicates preserve actual observed collections and scope coverage. PASS needs full relevant observation and actual equality. A direct supported counterexample can establish FAIL without observing every unrelated row; record the affected targets, actual contradiction and exact raw evidence IDs. Do not downgrade a real observed overlap or wrong callback merely because another region is unobserved.

An inaccessible method, unbound checkpoint, unreadable area, insufficient actual geometry, or unresolved contradiction is UNASSESSED. An actual established mismatch is FAIL. Missing new metadata is neither. Unknown rows name the required missingEvidenceMethod and a concrete detail. Strict case/aspect/public-rule/overall rollups are FAIL if any relevant result fails, otherwise INCOMPLETE if any is unknown, otherwise PASS. No average, partial positive score or self-review can turn an incomplete rule into a pass.

Seal independent per-specimen results and anonymous comparisons before reading any sealed reviews or assignment/version mapping. Later reconciliation is a new dated artifact, never a rewrite of the independent result.
