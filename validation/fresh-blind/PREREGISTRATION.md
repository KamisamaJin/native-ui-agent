# New-task three-arm forward test — preregistration

Frozen before any new task implementation. Independent designer's task is service visit rescheduling, with 17 public rules, 6 initial cases and 2 unseen repair holdouts. Designer could read only public upstream package/component architecture, not any Skill, old cases/report, implementation, assignment or improvement analysis. `design-freeze.json` commits public/private inputs. The anonymous arm assignment is committed there before implementation. Procedural access restrictions on shared filesystem; not a hardened adversarial blind.

## Arms and equal conditions

- No Skill, exact archived v1, improved v2. All start at the same pinned Reply and AlertToast commits with only common native host dependencies added. No previous feature implementation is copied.
- Same public brief, reference, model/actions API, common capture adapters and public example. Native observers, host reducer, dynamic category mapping and hardware are equal capabilities in every arm. New observer benefits alone cannot be attributed to v2 instructions.
- Fresh-context implementers inherit the same model/reasoning settings; exact service build, random seeds and token accounting are unavailable. No other agent or task history. Skill arms may read only assigned Skill, not competing versions or historical experiments. No builder may read oracle, assignment or another workspace.
- D0 implementation: maximum 25 active wall minutes for BOTH platforms. Build and the single public example may be used for compilation/integration; do not inspect rendered images or conduct visual self-review until D0 is sealed. This isolates the later visual-review/repair stage. Source reasoning, normal compiler fixes and API checking are allowed.
- Read-only self-review: maximum 12 active wall minutes after sealed D0 initial-case evidence is supplied. No code edits. Produce explicit case/rule findings and root-cause clusters with evidence. v2 may produce its evidence ledger using the generic coverage tool. All receive the same case input/actions and native evidence, but not private expected outcomes or holdouts.
- One repair: maximum 15 active wall minutes, based only on the builder's own sealed review and public design. No grader feedback. Rebuild and recapture after code changes. Final assessment reruns the 6 initial cases plus 2 previously unseen holdouts.
- Inter-stage operator/hardware queue time is excluded from active wall budget and reported separately. Agent phases can finish early. Shared hardware/cache contention makes timing descriptive, not a calibrated performance claim.

## Observation contract and safeguards

Production UI is called directly by common native hosts. Android uses an attached ComposeView during one continuous Paparazzi session, including real semantics OnClick callbacks, host echoes and external model replacement. Its scroll uses native ScrollState displacement; it does not prove physical touch/Activity lifecycle. iOS uses actual app + XCUITest, native AX and screen-point frames, real taps, same-process replacement and overlapping parent-scroll samples. Explicitly distinguish geometry, text-layout properties, pixels, source review and visual judgement. iOS does not expose generic SwiftUI fonts/padding/colors; unavailable evidence stays unassessed.

Native preflight uses unrelated simple controls, events, long content and model changes. Failures/corrections are retained. Host-only corrections require uniform reruns of affected outputs; retain original attempts and never repair product on one arm's behalf. Common material freezes before D0. No v2 changes after trial starts; new outcomes may motivate a later version only.

Widths320/390 are offered host widths; actual panel widths288/358 after host margins. Android requested fontScale1.0/1.3/1.8/2.0; iOS maps to large/xxxLarge/accessibility2/accessibility3 respectively, using platform categories rather than claiming numeric equivalence. Theme, direction, viewport and intended native test execution are checked separately. Minimum OS source compatibility is distinct from actual installed simulator runtime coverage.

## Outcomes (no target advantage required)

An independent designer/grader sees anonymized sources and evidence without Skill versions, builder identities, assignment or self-review findings until D0 and FINAL grading are sealed. The operator may see assignment to dispatch materials but does not grade outcomes. Initial grading is sealed before self-review disclosures; final grading before unblinding.

Report per platform and arm: confirmed defect/root-cause clusters, failing case×rule pairs, true positive / false negative / false positive, root-cause detection and exact-rule attribution separately. Miss rate = FN/(TP+FN), N/A at zero independently confirmed defects. Repair success = resolved confirmed D0 failures / confirmed D0 failures, N/A at zero; also report regressions and newly revealed holdout failures separately. A passing screenshot cannot stand in for an unexecuted callback, missing target, absent bottom coverage or an unseen caller update.

Report pass/fail/unassessed coverage and declared-scope checks separately, plus fixed 1–5 visual rubric scores with screenshot rationale. Native capability/transport errors do not count as product defects without evidence. Do not use a failed-to-execute test as a product pass. Publish all cases and mapping only after independent grading seals, including negative/equal findings. One new task × three arms × two correlated platforms remains a small descriptive experiment, not statistical proof of general effectiveness.
