## 先工程验证，再固定业务需求

1. 保留上一轮 `original-v3`。两组与评审共同使用成功派发门控：只有指定原生方法、
   唯一且启用的实际控件、相同输入／进程及精确事件区间成立，回调行为才可判 P/F。
   禁用、缺失、未执行及空区间本身都不能证明 handler 行为。
2. 用无关通用探针开发 v4：一次公开 iOS snapshot 获取本地层级、校验编译产物复用、
   动作后目标重新观测、减少定位中间图片及 Android 渲染开销。保留即时动作帧、
   原始回调区间和完整重叠滚动图片。缺证据仍为 U。
3. 冻结工具及预注册，再固定独立公开设计与私有原子验收。需求不由旧失败反推，
   不人为注入业务错误。通用验证与业务样本分别统计。
4. 相同上游、公共依赖、模型设置和预算下，两组各实现一次，D0 代码封存后读取自身
   分配工具的截图，封存只读自查，再修复一次。两组最终源码均封存后才生成隐藏
   场景具体原生输入，不再修改生产代码。
5. 两组开发周期结束后，才采集实验额外的统一评分／同源码反事实证据。独立评审
   依次封存双方 D0、双方最终、双方自查匹配、双方 D0 采集器配对，最后正式揭盲。

设计与预算详见 [预注册](PREREGISTRATION.md)、[操作协议](OPERATOR.md)、
[实现者契约](BUILDER-CONTRACT.md) 和 [独立设计](design/public/brief.md)。

## 原生接入和能力边界

测试宿主直接调用固定上游 Reply／AlertToast 生产模块中的新增组件，桥接层只解码
输入并转发回调。它没有复制一份测试专用业务 UI 或计算规则。两组使用相同依赖配置；
原生观测器的实现差异属于被比较工具本身，并分别保存源码指纹。

iOS 通过真实 App＋XCUITest 在模拟器里采集 AX 与截图并执行 XCUI tap。Android
通过 Paparazzi/Layoutlib 渲染真实 Compose 组件，调用实际 Compose semantic OnClick，
不声称验证了操作系统物理触摸。字号、内部 padding 和真实 hit 区域在缺少所要求的
运行时检查时保留 U。截图只能支持明确的视觉／像素结论。

局部 selector 是这次新增组件的测试契约，不要求旧项目全局登记业务 ID；本轮也不能
证明仅凭模糊 testcase 就可无接入测试任意历史页面。原应用导航、后端和真实网络行为
不在组件试验范围内。

## 指标口径

运行时业务、视觉、接入、运行时能力、输入成员和源码 API 六种分母独立。
全部冻结验收行保留，支持不了的方面不能从分母删除，也不能由源码声明代替。

业务漏检仅计算独立确认且已建立成功原生刺激的业务反例；自然反例为零时记 N/A。
确认发现误报占比使用 FP/(TP+FP)，没有完整负例宇宙就不称经典误报率。
修复按同一 D0 失败行到最终 P/F/U 统计；F→U 未解决，U→F 为新可评估失败。
隐藏场景与自查初始场景分开，重复原子行不当作独立 bug 数。

连续开发时间保留所有屏障、排队及首次失败尝试；必需阶段之和不称活跃推理时间。
额外采集、共同工程和独立评分单列。旧版没有输出的内部计时标未知；模型 token
与账单未被宿主暴露，不伪造金额。完整逐命令数据见 `cost-summary.json`。

## 审计入口

| 资料 | 内容 |
| --- | --- |
| `*-freeze.json`、`*-commitment.json` | 工具、方法、设计、分组与评估格式封存 |
| `design/private/evaluator-prep/` | 各版原始评估器、负向控制、原始规范与格式校准 |
| `design/private/evaluation/` | 独立原子评分、自查逐行匹配及同源码转移矩阵 |
| `private/submissions/` | 不可变 D0／最终源码、原始自查、修复、编译失败及语料封存 |
| `private/grade-capsules/` | 匿名原始证据及身份／路径投影，原始图像字节保留 |
| `evidence/` | 有效、公开集成和被废弃首次尝试的原始 PNG、JSON、命令日志 |
| `result-summary.json`、`observation-summary.json` | 固定分母、全部转移和实际逐状态／目标几何事实 |
| `failure-index.json`、`artifact-manifest.json` | 所有 F/U、命令失败与发布文件指纹 |

这是共享文件系统和可识别数据格式下的程序性匿名，不是技术隔离的严格双盲。

人类金标准。一个任务和相关平台只支持描述性结果，不支持通用质量因果结论。
