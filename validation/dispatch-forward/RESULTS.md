# WaterRound：派发门控修复与 v4 观测优化盲测

本轮证实了**采集成本明显下降**，没有证实覆盖或业务漏检改善。同源码配对新增 2 个可评估原子项、失去 3 项，净 −1；新版发现了一个语义标签共因，但只明确记录了八个失败状态中的两个。所有分数、失败、未评估和揭盲后发现的观测问题均保留，没有按结果修改工具、需求、容差或业务代码后重测。

## 先固定什么，再做什么

先修复共同回调门控，再冻结 common-v3/candidate-v4 和通用探针；随后独立上下文设计全新 **Garden Water Round**，在固定上游的 AlertToast Swift 包与 Reply Compose 生产模块中实现。该组件涉及两种放水方式、精确整升计算、保护水量确认、短缺/暂停/提交优先级、受控模型替换、带派生字段的 typed callback，以及长内容、RTL、深浅主题和文字缩放。这是新编写的复杂业务需求，未从上一轮退款/换货等失败条件改名复用；也不是上游维护者提出的真实产品路线图。

[公开需求和参考](design/public/brief.md)、[API](design/public/api.md)、[设计封存](design-commitment.json)、[预注册](PREREGISTRATION.md)、[实施资源约束](BUILDER-CONTRACT.md)、[操作顺序](OPERATOR.md)均保留。工具在设计前冻结，业务盲测期间不变。

两组均使用 Skill，相同宿主模型默认设置与公共依赖；本轮比较的是 **common-v3（v3＋共同成功派发修复）** 和 **candidate-v4（相同修复＋通用观测优化）**，不能解读成有/无 Skill 的新对照。每组一次实现、一次只读自查、一次修复；25/12/15 分钟分别是上限，允许提前完成。两份首版源码先封存，再交付各自工具的四场景截图；两份最终源码都封存后才生成两个隐藏场景的原生输入。最终没有因隐藏结果继续修复。

独立评审依次封存两组的 D0、FINAL、原始自查发现匹配、同源码旧工具配对，再正式揭盲。八份封存及原始交付物均有字节指纹，顺序由 [verify_blind_stages.py](verify_blind_stages.py)检查。共享文件系统、可辨认的工具输出和命名意味着这只是程序性盲法，不是隔离的双盲实验；没有人类金标准、重复试验或随机化因果结论。

以下均为冻结原子行，不是独立 bug 数。P/F/U 分别为通过/失败/未评估。

| --- | ---: | ---: |
| 业务漏检：成功请求刺激后的独立 F 未被自查明确报告 | N/A：没有自然 F | 6/8，75.0% |
| 确认映射发现误报占比 FP/(TP+FP) | 0/5，0% | 0/8，0% |
| D0 全运行时漏检，描述性口径 | 7/12，58.3% | 14/22，63.6% |
| D0 运行时 F→FINAL P | 12/12，100% | 20/22，90.9% |
| D0 业务 F→FINAL P | N/A | 8/8，100% |
| D0 运行时 U | 1092/2262，48.3% | 1027/2262，45.4% |
| FINAL 六场景运行时 U | 1625/3470，46.8% | 1545/3470，44.5% |
| FINAL 冻结运行时 P/F/U | 1843/2/1625 | 1922/3/1545 |

两组运行时分母相同，但生产实现不同，**不能把 U 的组间差值归于新版工具**。两份 D0 通过同一工具交叉采集后的净覆盖收益接近零，见下一节。未映射确认发现旧/新分别 7/2 条，旧组另有一条不确定发现，不能自动算误报；没有完整 TN 宇宙，经典 FP/(FP+TN) 不可得。

新版的八个业务 F 全是 C02/C03 四个动作后状态的 `consent.text`：原生合并名称包含 `✓, `，违反精确确认标签契约；自查明确报告 a03 两项，a04/a05/a06 六项未逐状态报告。这是一个无障碍名称共因，不是八个计算或 handler bug。源码改用非文本勾号绘制并显式提供名称，八项最终均 P。**共因修复成功不等于八个状态都被检查过**；不能用修复结果倒填检出率。回调 payload、业务金额错误不能由这些 label F 推出。

两组 iOS 首版各有十二行额外 disabled fade 的像素失败，修复均通过。原子行重复多个状态、颜色方面，不能称为十二个独立样式缺陷。Android RTL 字形顺序也被自查并修改，但冻结计划没有可精确映射的相应原子行，该发现保留为未裁定，不补造分母。[原始自查与修复](private/submissions/)、[逐项匹配](design/private/evaluation/selfreview/)全部公开。

FINAL Android 每组各有两行原生可见高度 `47.99994000000004 < 48` 的冻结 F。这一约 `0.00006 dp` 的差值暴露严格数值边界的脆弱性，**不构成有意义的按钮过小证据**。它使新版原始修复率停在 20/22；没有事后增加 epsilon、改 F 为 P，或把它宣传为真实修复失败。另有 candidate-v4 隐藏 H01 一行 iOS consent 可见 AX 高度 28 pt（要求 44）的 F，独立保留；它也不证明物理点击区域大小。

旧组隐藏运行时 673P/2F/533U，新组 689P/1F/518U，各 1208 行。旧组两 F 是上述数值边界，新组一 F 是 iOS 可见边界。两组没有 D0 P→FINAL F 回归，也没有 D0 U→FINAL F 新失败；隐藏场景不混入 D0 自查漏检分母。完整平台、分母、迁移和失败 key 见 [TABLES.md](TABLES.md)、[result-summary.json](result-summary.json)、[FAILURES.md](FAILURES.md)。

两份源码合计 4524 个运行时行：旧工具 U 为 2118，新为 2119（46.82%→46.84%）；新增 2、失去 3、净 −1，无 P↔F 冲突。差异全在新组源码的 Android C03/a02：新版观察到 drip enabled/selected，旧版观察到 status 和 submit enabled/text。目标重新定位改变了视口覆盖，**看见目标不等于看全该状态的所有业务元素**。

几何完整滚动状态，D0 每组 16/16，FINAL 每组 24/24。成功原生激活 D0 每组 30/38、FINAL 每组 48/60；禁用等不可派发情况仍保留 U。FINAL 自身采集动作后语义目标完整可见旧/新 58/60 与 60/60；同一旧组 FINAL 改用 v4 采集为 60/60。同源码新组 D0 的旧/新为 37/38 与 38/38。这支持局部目标视口改善，不能推出整体覆盖增长或动作业务正确。[逐动作原始事实](observation-summary.json)可复算。

## 回调前置条件和未评估缺口

共同 `callback_verdict` 要求实际尝试且成功、指定原生方法、唯一启用控件、相同输入/进程和精确绑定的原始事件区间。未执行、禁用、目标缺失、方法不符或仅有空区间，预期零事件也为 U。成功派发后的错回调/漏回调才有资格判 F。调用方替换另须实际输入索引前进；后续滚动不扩大回调窗口。共同修复不计为 v4 优势，上一轮分数不回写。

FINAL 每组 1160 个运行时能力行全部 U，包含字体、内部 padding、物理 hit 等方面。iOS 没有通用实际样式检查层；Android 原始节点有部分 `font_sp/font_weight/color_argb/touch_bounds_dp`，但没有冻结评估方法要求的原生检查来源/绑定/probe envelope。这是共同的来源格式或能力缺口，不等于所有原始字段都不存在，也不能由源码、图片或 semantic bounds 补造通过。[原始字段可用性记录](design/private/evaluation/paired-d0/)与严格评分同时保留。

其余 U 也分别保留：FINAL 旧/新有 240/162 行缺原生目标或字段；两组各 94 行为 iOS 被阻止的派发没有 `dispatch.binding_before`，未能建立前置身份、另各 94 行为 Android 未证明成功派发，另有布局冲突和像素对比不足。前者是 iOS 收据缺失触发的保守门控原因，不能据此断言原生输入实际错误；两类均不能解释成业务正确。输入成员 1260P、源码 API 113P 的分母不并入运行时来抬高覆盖。

揭盲后整理图库时，多图预览曾把原始字节完全相同的两张 iOS PNG 显示为不同内容。独立的 SHA-256、Pillow 像素核对和另一评审上下文确认原文件相同，最初的采集器空白帧推断已撤回。这是 [预览诊断记录](harness-failures/image-preview-discrepancy.json)，不计为采集器、渲染或产品失败，也未更改评分。[GALLERY.md](GALLERY.md)保留原图及更正，避免将预览误读混入质量结论。

独立评审的揭盲后解释和预览误读撤回见 [解释补充](design/private/evaluation/post-release/interpretation-addendum.md)；原始解释版本也保留，不替换封存评分。

## 工程收益归因与保留失败

v4 的单次公开 XCUI 快照遍历、经源码/工具链/产物验证的编译缓存、几何定位追踪替代冗余搜索图、动作即时收据后再定位，以及 Android 两帧稳定/完成信号截断 GIF，均在新设计前完成通用验证。原生动作、完整滚动扫描、输入和进程仍重新执行；缓存不复用旧证据。详见 [ENGINEERING.md](ENGINEERING.md)。

以下两组共享或属于实验执行，不计为 v4 收益：成功派发门控；公共宿主和依赖；输入命名空间修正；评估器当前 model 哈希编码及 iOS 完整 App 像素比例校准；发现精确匹配格式；评估阶段原图解码有界缓存；报告索引目录过滤。全部旧文件、修正封存和执行失败保留。冻结评估器本体没有改变。

计划 68 次业务采集全部退出 0，保留 1474 个快照记录；这只表示采集执行成功。另有首次翻译 8 次命令（4 次 iOS preflight 无原生测试、4 次 Android 执行成功但映射废弃）和公开集成 4 次命令/19 个快照；通用测试另有 2 次有意缺失目标导致的 iOS 非零退出。旧组修复验证中的一次 iOS14 API 编译失败和后续兼容修正也保留，不能倒填成先前自查已发现的业务问题。

## 复现与结论边界

[REPRODUCE.md](REPRODUCE.md)说明原生重渲染与无 SDK 审计的区别。已发布的 PNG、原生观察、编译宿主源码、生产源码封存、输入、评审及日志有指纹；DerivedData/xcresult、SDK 和自动诊断视频不分发，省略项有原因/指纹，所有断言图片保留。完整评分复放重跑冻结匹配器、原始像素采样、引用检查和精确行算术；视觉语义判断依然是 AI 的独立标注，不是可重放的人类金标准。

iOS 实跑为模拟器 XCUI；Android 为 Paparazzi/Layoutlib 内的 Compose semantic OnClick，未验证 Android OS 物理触摸。测试调用真实生产模块的新组件，使用本次功能局部 selector 和薄桥；没有验证模糊 testcase 对任意既有页面的自动定位、完整应用导航、后端或设备矩阵。iOS14/macOS11 源码兼容编译不等于在所有最低系统版本运行。

本轮适合发布的是**门控更诚实、采集更便宜**的通用能力。大比例 U、逐状态漏检、视口覆盖交换、数值边界脆弱性依然存在；不能据此宣称 native PR 质量已整体提升或样式能全自动精确验收。
