# Dispatch, observation cost and fresh UI forward test

Recorded before new tools, business design or implementations. Prior trials and
scores remain immutable. This trial tests v3 plus a COMMON callback-precondition
correction against v4 observation optimizations. Both arms use a Skill.

## Engineering before design

First require demonstrated native dispatch, actual route and bound input/event
interval before a callback BEHAVIOR can pass or fail. Observer-blocked, unavailable,
unsupported or merely observed intervals stay unassessed, even for expected zero.
Caller-update quiet intervals require explicit successful update proof. The same
gate is mandatory in both arms and in the independent evaluator. Literal interval
facts may be recorded separately, never counted as proven behavior.

Freeze v3+gate before optimizing. Optimize only with unrelated generic native
probes: AX extraction, stable build reuse, bounded post-action target observation
and rendering overhead. Never reduce fonts, shorten business input, omit required
states or give cached evidence a new input binding. Cache keys must cover actual
compiled sources, bridge, SDK/toolchain and compile configuration. Missing hit-test
attributes are unavailable, not replaced with geometric guesses.

Generic capability expectations precede native runs. Retain failed attempts and
original sources. Compare same inputs/source and report cold/warm build, native
test, extraction/export, snapshots, action-target coverage and every loss, not only
net coverage. Original v3 is retained; the shared correctness fix is not counted as
an optimization benefit.

## Fresh task and independent contexts

Only after the candidate freezes, an independent fresh context designs a NEW
complex controlled component, public API/design and private acceptance. It cannot
read tools, previous source, scores, failures or this round's generic probes.
Resource envelope is fixed now: four initial cases and two unseen holdouts; up to
two models, eight native actions and two full-content visual checkpoints per case.
Include conditional business decisions, caller-controlled state, a numerical
summary, disabled/submitting states, long content and responsive/theme/type/RTL
variation within this envelope. This prospective envelope applies equally to both
arms and is not an optimization outcome. No cartesian product is required.

Commit public reference and all private atomic/member expectations before builders
see the task. Keep business behavior, visual/style, integration/API and unavailable
platform capabilities separate. Requirements must name actual observation methods;
do not demand a nonexistent universal SwiftUI style tree. No deliberately injected
business bug. A zero natural business-defect denominator is N/A, never a forced win.

Two fresh implementation contexts start from the same pinned Reply/AlertToast
upstreams, model configuration and budgets: implementation 25 minutes, read-only
self-review 12 minutes, one repair 15 minutes. Public build/integration is permitted
before D0 seals, product-image self-review only afterward. Identical public bridge
and input operator; assigned tools only, own evidence only. Both D0 sources seal
before reviewer feedback; each own review seals before repair. Both final sources
seal before held-out concrete inputs are generated. No grader feedback to builders.

Independent grading can follow the development loop: evaluator receives only
anonymous D0 source/raw evidence first, seals both D0 grades, then final evidence,
seals both final grades, then sees self-reviews for exact matching. Formal assignment
is withheld until main grades, matches and paired-source collector assessments all
seal. Root performs orchestration/arithmetic, not business grading or code repair.
Shared filesystem/recognizable formats provide procedural blindness only.

## Coverage and comparisons

Main quality grading uses the same frozen v4 collector on both source archives.
Each self-review receives only its assigned collector's D0 evidence. Additionally
pair old/new collectors on BOTH D0 sources, with equal inputs and intended actions;
credit sufficient legacy raw evidence independently. No missing-new-field shortcut.
Report exact realized actions and snapshot/binding evidence.

Required cells and parameter members are fixed before implementation. PASS requires
ALL named preconditions, stimulus and requested methods for that atomic aspect.
No source declaration substitutes for native rendering; no empty event interval
substitutes for dispatched activation; no method fallback proves requested method.
Style, business, source/API, platform and per-state denominators are separate.

Primary business miss rate is FN/(TP+FN) over independently confirmed BUSINESS
counterexamples with established successful native stimulus. Integration identifiers,
visual clipping and observer failures are separately reported, never relabeled as
handler bugs. Preserve original finding count, uncertainty, duplicates and descriptive
defect clusters. False discovery share is FP/(TP+FP), not classical FP/(FP+TN) without
a complete negative universe. Repair is same D0 F to final P / D0 F; F to U unresolved;
regressions and newly assessed failures separate; holdouts separate. N/A for zero.

Primary observation metrics: required runtime assessed/required, full-state interval
coverage and target/indicator visibility after each required action, plus native
stimulus-method establishment. Pixels alone do not prove actual font or hit region.

## Cost and publication

Record continuous per-arm start-to-own-final-evidence timestamps, all phase walls,
feedback collection, build/cache, native execution, export, visual review and failures.
Also report the sum of required sequential development segments and expose intervening
queue/barrier time; never silently subtract it or call it measured active reasoning.
Independent oracle/grading, common setup and generic engineering are experiment
overhead, separately counted. Reused captures count once. Command sums with parallel
slots are not end-to-end wall. Use the same native slot count and fixed case ordering
for both arms; same-source collector pairs distinguish acquisition cost from code.

No universal quality/speed causal claim from one task and correlated platforms. Keep
negative results, unresolved/U, failed capture attempts, original grading and scope
deviations. Do not retune tools or acceptance after reading fresh business outcomes.
Publish source, readme, raw assertion images/JSON/logs, complete score ledgers, timing,
failure inventories, seals and reproducible cache-free audits, then update the repo.
