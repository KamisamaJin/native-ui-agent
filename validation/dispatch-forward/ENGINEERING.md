# v4：先修正判定，再优化观测

这些实现和通用验证都早于 WaterRound 业务设计交付；业务盲测期间工具保持冻结。
`original-v3` 保存上一轮工具，`common-v3` 是本轮共同基线，`candidate-v4`
与当前发布 Skill 的工具文件一致。不能把共同修复算成 v4 独有收益。

## 共同修复：成功派发是回调行为断言的前置条件

两组与独立评估器使用同一 `callback_verdict`。PASS/FAIL 前必须有真实尝试和
成功结果、指定原生方法、唯一且启用的实际控件、相同进程与调用方输入，以及精确
绑定的原始事件区间。iOS 为 XCUI tap，Android 为 Compose semantic OnClick；
后者不声称验证了系统物理触摸。

`blocked_disabled`、目标缺失、未执行、方法不符、仅观察到空区间均为 U，预期零回调
也一样。成功派发后的漏回调或错误 payload 才可判 F。调用方替换的静默断言要求实际
输入索引前进。iOS 在动作即时帧结束回调区间，后续滚动不能扩大该区间。

评估器也对所有要求派发证明的动作后业务状态执行门控。输入成员、源码声明和字面
事件数量只证明各自的事实，不能绕过门控。通用原生探针包含成功、静默、错误回调、
禁用和缺失目标；独立评估器另外保留 43 项原始负向检查及 40 项编码/溯源检查。

## v4 的通用实现

- iOS 每帧使用一次公开 `XCUIElementSnapshot` 取得层级和本地属性，保留真实父子
  关系。实际派发前仍查询目标的原生可交互性；其它节点的 hittable 没有测量就写 null，
  不用矩形猜测。层级、图像的输入 epoch 或几何不一致时，相关断言保留 U。
- 动作后保留即时帧与回调收据，再按当前几何有界地重新定位原目标或 `after_target`。
  不二次点击；缺失、歧义、绑定变化和仍在视口外均不变成通过。过大目标的中心可见与
  完整可见分别记录。
- 定位过程中默认保留几何追踪，避免每一步都生成冗余 PNG；可开启
  `trace_reveal_images`。完整状态扫描仍保留全部重叠图片，不缩短文本或省略状态。
- iOS `--build-cache` 只复用校验过的编译产物。键覆盖实际源码及路径、桥、模板、SDK、
  工具链和编译选项；同时校验构建产物与编译工程。每次重新注入输入、启动新进程、
  收集收据与图像；产物被篡改时拒绝复用。路径变化也是合法的 cache miss。
- Android 保持同一个已挂载 ComposeView，以两个布局帧等待替代八帧；只有原生采集
  状态机完成后才用专属结束信号停止 GIF 的剩余帧。没有提前跳过计划动作或完整扫描。

这些工具仍不提供通用 SwiftUI/Compose 样式树。实际字号、内部 padding 和物理 hit
区域缺少所要求的运行时检查时继续 U；截图和源码均不能代替这些属性。

## 业务设计之前的验证

共保留 15 次原生测试和 241 张原始 PNG，包含有意缺失目标导致的 iOS 非零退出。
独立验证另选了中性长内容组件，两端各执行一次；每端类型化检查 5P/0F/1U，五个
状态均有完整采样。Android 的画布色预期错误单独记为视觉失败，未改成通过。

同一中性组件的描述性采集数据：

| 采集 | common-v3 | 优化后 |
| --- | ---: | ---: |
| iOS 动态目标/完整状态，命令秒数 | 122.352 | 31.096 |
| Android 动态目标/完整状态，命令秒数 | 11.741 | 3.531 |

iOS 优化样本多一张动作后证据图。运行期间存在共享硬件、Gradle/编译缓存和其它
作业，以上不是隔离环境速度基准。最终冻结工具另外验证了合法路径变更 cache miss
和同签名的 cache hit；warm 的构建校验耗时 0.180 秒，实际测试 25.183 秒。
不同输入、进程身份和收据均重新生成，不能把 warm 的总耗时变化全部归于缓存。

原始数据见 `generic-summary.json`、`generic-evidence/` 和
`independent-generic/`；`verify_generic.py` 可在没有 SDK、模拟器或旧缓存的检出中
验证冻结文件、原生来源、收据、状态、目标视口、缓存与全部图片指纹。

## 实验调度与评估格式修正

这些修正不属于 v4 工具收益，原文件和失败记录全部保留：

1. 执行脚本 `operator.py` 与 Python 标准库同名；实现开始前改为
   `trial_operator.py`。
2. 第一份业务输入翻译重复使用状态 ID，并与保留名冲突。iOS 四次 preflight 拒绝；
   Android 四次执行成功但采用了已废弃的映射。随后共同翻译改为有命名空间的动作和
   完整采样 ID；模型、业务源码、工具和预期不变。两组使用同一 v2 映射，初始尝试
   作为额外调度成本保留。
3. 独立评估器初版把整个 fixture 文件 SHA 与原生当前 model SHA 比较，且依赖绝对
   路径。评分前以独立 Foundation/kotlinx 合成向量校准格式，保留初版封存，并新增
   v2 适配封存。7 个向量/平台和 83 项检查通过，没有读取候选源码/结果，没有改变
   预期、门控或分母。原生 model 哈希与文件指纹分别保存，迁移检出继续验证原哈希。
4. iOS PNG 是完整 App 截图，不能用窄 viewport 宽度计算像素比例。评分前仅依据
   冻结采集器源码、中性探针的几何元数据和合成图片校准为 `PNG / app_frame`，并
   校验两轴比例、原生 scale 和非零 App 原点；Android 保留全 View/dp 规则。初版
   协议与 v2 均保留，新增 v3 封存及 29 项几何检查，总计 112 项检查通过。没有
   读取业务源码/图像，没有改变业务预期、像素容差、原生匹配器或门控；这是共同
   评估基础设施修正，不计为 v4 独有收益。
