# Prospective operator and cost accounting

This detail is fixed before the fresh design is delivered to the root or builders.
It changes no tool or business expectation. Both arms use one iOS slot plus one
Android slot during their measured development workflow, cases in lexical order.
Fresh upstream checkouts and common test dependencies are identical. Gradle inputs
are explicitly bridged to the test worker and native capture tasks cannot be
mistaken for up-to-date cached evidence. Compiler caches may be shared by the host;
there is no isolated cold-SDK or independent-machine performance claim.

1. Both builders seal D0 source and public-integration reports before image feedback.
2. Capture each arm's four initial cases using ONLY its assigned collector, on its
   still-frozen workspace. Source hashes must match the D0 capsule. Platforms may
   run in parallel, cases within a platform are sequential.
3. Start that arm's 12-minute read-only review when its own corpus seals. Do not
   wait for independent grading. Seal review, then one 15-minute repair. No grader
   findings, other arm's source/evidence or holdouts are supplied.
4. Seal both final sources, then generate all held-out native inputs. Run each arm's
   six final cases using its assigned collector. No further business code changes.
   The measured continuous per-arm interval ends when its own final corpus seals.
5. AFTER both measured loops finish, collect experiment-only uniform-quality and
   counterfactual evidence: v4 on baseline D0/final, and common-v3 on candidate D0.
   Candidate D0/final v4 captures and baseline D0 v3 captures are reused once, never
   charged twice. Use fresh audit hosts/source capsules so final code cannot leak
   into an initial replay. These extra native runs cannot contend with the primary
   measured feedback loop. Later grading cost is separate experiment overhead.
6. Independent grading receives anonymous D0 common-v4 evidence/source, seals both
   grades, then final common-v4 evidence/source, seals both grades, then own reviews
   for matching. Counterfactual raw corpora come after matching seals; both paired
   assessments seal before formal assignment release.

Planned source-native acquisitions: 16 initial assigned-tool commands,24 final
assigned-tool commands and28 experiment-only common/counterfactual commands =68.
Public integration and generic engineering are separately retained. This is a count
of planned attempts, never a claim of 68 successful tests. Native failure without
adequate evidence yields U; unexecuted actions cannot create business failures.

Report both raw continuous start-to-final-corpus duration and individual sequential
segments: implementation, initial collection, self-review, repair and final
collection. Source/holdout/other-arm barriers, service interruption and operator
queue are explicit timestamped gaps. Do not silently subtract them or call the sum
of segments a measured uninterrupted run. Also report full experiment wall/cost,
including extra acquisition and independent grading. Build validation/native test/
export subtimings and all retries/failures remain available.

The same-source pairs on both D0 implementations isolate observation coverage and
acquisition cost from code differences. They are still small descriptive samples.
Business miss/repair metrics require the common native stimulus gate, and do not
count identifier/bridge failures or literal empty intervals as handler bugs. The
required runtime denominator still includes unsupported/unobserved cells; coverage
losses, post-target misses and missing requested methods must be visible.
