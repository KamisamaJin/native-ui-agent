# 独立通用协议探针，修订 1

本文件与 `cases.json` 固定三个无业务含义的小任务：临时工作台、带依赖的计数器、声明证据账本。它们只检查工具协议，不植入或评分产品缺陷，也不是后续业务盲测题目。

独立制定者只读取了 `native-ui-agent/SKILL.md`、其公开参考文档及所列入口的接口/相关实现片段；没有读取 `validation` 下任何历史业务需求、结果或候选实现。读取清单及制定时的文件摘要见 `readset.json`。本目录中的期望不从现有单元测试或实际运行结果推导。

本次先固定任务与判据。封存时没有执行待更新工具，没有启动原生 SDK，没有创建、删除或修改全局设备，也没有修改生产工具。接口接入后按相同封存版本执行。后续修订必须另建版本并说明依据，原始版本、失败及退出码保留。

## 三个小任务

1. 临时工作台：一次调用申请一个私有目录并启动确定性的临时进程树，同时借用一个已存在的目录和一个哨兵进程。调用退出后只回收有本次所有权的临时资源，保留借用对象、源码、缓存和证据。正常、异常、取消和进程崩溃分别执行，不以单一 `finally` 用例代表全部生命周期。
2. 带依赖的计数器：一个临时 actor 在收到动作时把计数值和事件写入文件。后续动作声明它依赖的是成功派发还是某条断言通过。检查失败前置条件不被好看的后续状态掩盖，实际当前状态的独立事实也不会被无差别丢弃。
3. 声明证据账本：用小块色板、源码文本和明确标成协议样本的节点/回执记录，逐项询问证据能支持什么声明。该任务不把合成节点记录称为原生执行。组件、宿主、系统三种责任与视觉、像素、静态、原生属性、动作证据分别检查。

## 结果含义

- `P`：本探针明确要求的协议行为有实际证据支持。
- `F`：探针判据被实际违反；这是工具协议发现，不能计作产品缺陷。
- `U`：接口、平台能力或证据不足，保留分母，不算通过。
- `X`：计划或证据输入被明确拒绝；只有某个负例预先要求拒绝时，`X` 才是该探针的预期结果。

待测工具自己的 `passed/failed/unassessed/error`、退出码和原因原样保存，另行映射到上述探针结果。预期拒绝不能被叫作原生通过；正常采集成功也不等于交付接受。

## 共同执行边界

所有文件和进程只在新的 `validation/managed-forward/probes/runs/<run-id>/` 或项目专用 cache 子目录内创建。每个子例使用新的根、令牌、输入、进程和输出；测试不会重用旧证据。借用对象也由探针在本轮提前建立，不能选择用户的现有工作进程。不得枚举后批量清理设备、进程或目录，不得改动 `.git`。

资源回收对象必须同时有持久所有权记录和活体身份匹配。一个 PID、路径前缀、目录名、进程名或“启动前未发现”标记单独都不足以授权回收。PID/start identity、进程组、所有权令牌和原始路径/inode 等采用平台能够实际提供的事实。工具不能把记录声明当成活体身份。

`cases.json` 内的每个 `variants` 成员是单独的验收行。每行都记录原始观测，不以组内其他成功子例填补。已实现且合法的正例须成功，合法的缺证据必须为 U，畸形/伪造输入须拒绝。不能用“所有东西一律拒绝”通过负例。

无 SDK 资源用例必须运行真实临时进程和文件系统操作；动作若有通用派发接口，也使用实际 actor 的文件/事件变化。仅原生格式才支持的门控可以先用明确标注的协议样本验证判定函数，随后必须由 `native-requirements.md` 中对应的实际原生用例补足。合成回执的 P 只表示校验器逻辑通过，不建立原生能力或产品行为结论。

确定性动作/文件存在检查的总等待上限为 5 秒；终止和回收的总上限为 10 秒；持有活体租约的并发挑战观测 2 秒。均以单调时钟计，保存轮询轨迹及实际耗时。超限记 F；操作系统明确不支持的身份能力记 U，不扩大超时消除失败。SDK 时限不套用这些数值，实际配置须另存。

取消分为 SIGINT 和 SIGTERM；崩溃用只针对本轮管理者进程的 SIGKILL。SIGKILL 不能运行退出处理，因此要求下一次显式 reconcile 在本轮根内有界地回收可证明归属的遗留资源，而不是要求被杀进程当场完成清理。reconcile 前后的活体、文件和日志事实都保留。

验证者最后可以为防止自身测试泄漏执行兜底回收，但必须先落盘待测工具的结果与资源快照，单独记录 `harness_emergency_cleanup`。兜底动作不能使原始失败变为通过，也不能删除原始输出。

## 原始证据与封存

每行的最小证据是输入字节、待测公开入口及参数、待测工具源码摘要、stdout/stderr、退出码/信号、实际进程身份与时间序列、文件清单及字节 SHA256、待测工具收据、独立判据结果。对拒绝保留拒绝前是否发生派发或资源副作用的实际记录；不能只匹配错误文案。

每次运行写入新的目录，原始证据只追加。修复后另跑，明确引用旧失败。不可删除失败行、把原始输出改成最终状态、把依赖不成立写成产品失败，或以汇总成功遮盖未执行行。复验报告保留首次与最新状态及未解决项。

`seal-manifest.json` 固定本目录所有任务、判据、接口需求和读取清单的字节摘要；它不证明作者独立或需求完备。`seal-manifest.sha256` 固定清单自身。此封存不是生产工具冻结；工具实现后须另存实际执行工具的源码摘要。

新增接口只需提供 `interface-requirements.json` 中的能力，可以使用 CLI 或公开 Python API。验证适配器只能翻译调用和规范化传输，不能在适配器中补写清理、前置条件门控或责任判定语义。详细原生要求见 `native-requirements.md`。
