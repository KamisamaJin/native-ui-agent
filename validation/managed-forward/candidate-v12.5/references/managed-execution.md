# Managed execution

`ui_loop.py native` runs resource admission and evidence responsibility checks automatically. It generates guarded native actions; neither arm selection nor remembered optional calls is needed. Raw source, captures, review results and errors remain outside disposable scratch.

## Resources

Optional project `resources` policy: `root`, `max_bytes` (default 20 GiB), `min_free_bytes` (5 GiB), `max_simulators` (1), `sample_seconds` (2), `ttl_seconds` (86400), `command_timeout_seconds` (900). The scratch root must be disjoint from production source/evidence, newly created or marked by this owner. A live OS lease prevents concurrent acquisition/deletion. There is no global cache/device purge.

iOS `native_options.simulator: "managed"` requires `resources.ios: {device_type, runtime}` using exact installed IDs. Only journaled creates are deleted; caller-supplied device UUIDs are borrowed. Every invocation removes its owned devices. Compiled scratch persists under its budget between feedback cycles and is removed on final capture, error, or explicit cleanup. Borrowed project build paths are measured/budgeted but not deleted. Shared SDK/Gradle caches are not managed.

The approved native plan supplies the platform to `native_options(platform=...)`, including standalone iOS bridges with no package. Unknown platform options are rejected before acquiring native resources. Low free space blocks native acquisition/commands; it does not block reading and routing existing source/image evidence.

Public Python API: `with resource_manager.Resources(config, output, final=False) as resources:`; `resources.directory(name)` acquires one owned directory; `resources.release(name)` releases a directory when no managed process uses scratch; `resources.native_options()` acquires native handles; `resources.run(argv, env=..., stdout=..., timeout=None)` supervises the actual process group. `finish()` closes the lease once; repeated calls retain the original receipt. The root's two generation-numbered journal copies, OS lock, markers and acquisition tokens provide ownership, not a filename prefix/PID alone. Reentering one exact root reconciles an interrupted owned process/device; a damaged checkpoint can recover from the independently durable copy. SIGKILL cannot execute Python cleanup; reconcile is required on the next entry. `resources.json` records samples, policy, primary error, cleanup errors and leftovers; original events/journal are copied alongside it. Peaks are sampled allocated bytes, not exact transient/APFS physical peaks.

CLI: `python scripts/resource_manager.py cleanup --config PROJECT.json --output FRESH_RECEIPT_DIR`. `inspect` also acquires the exclusive lease and reconciles stale owned processes/devices before returning its state.

The default service publishes `cycle.json` only after resource finalization succeeds and pins `resources.json`. A cleanup exception retains `service-error.json` and the raw resource error; it cannot leave an accepted cycle. Reusing an output directory is rejected before touching its original evidence. Final image completion verifies the pinned final resource receipt as well as the native/source gates.

Collector coverage reports bind `request_sha256` to the exact native request bytes. Only the controller's independently rebuilt execution receipt binds `execution_sha256` to the approved plan. The older iOS inner field mislabeled the request digest as execution identity; preserve its original bytes but do not use that field as plan proof. Outer execution reconstruction and coverage remain required.

## Action guards

Approved launch actions may declare `depends_on: [earlier indices]`, `callback_dependencies: [{action_index, expected_events}]` and `preconditions: [{target, property, op, expected}]`. If omitted, the default dependency is the preceding action (the first has none). An explicit empty list is an independently approved new branch. Callback predicates require both the original successful stimulus and the exact independently approved event interval; a dispatch-only dependency does not require the callback assertion to pass. Unknown, forward/self/cyclic dependencies are rejected before dispatch. Supported properties are `present`, `enabled`, `selected`, `label`, `value`; operators are `eq`, `contains`. Native absence outside a proven complete scope is unavailable, not guessed false.

The compiler fixes dependencies and predicates in `execution.json`. Both native templates check them before dispatch; blocked descendants do no extra native action or target sweep. One original root diagnostic remains. `action_guard.verify_observation(actions, observation, platform)` independently replays successful stimulus/method, process/input/event binding and actual predicates. Successful dispatch is distinct from a matching callback expectation. State assertions depending on an unestablished route retain U and the upstream receipt. Independent sibling branches can still collect their own evidence. Source-bound final/full admission still requires every mandatory item.

## Responsibility contracts

Set `responsibility_ref: {source, pointer}` to an array inside the separately approved design lock. Each atomic entry has `id`, `clause`, `priority` (`must`/`advisory`), `owner` (`component`/`bridge`/`integration`/`host`/`system`), `method`, `subject`, `rule_ids`.

Native methods `control`, `geometry`, `callback`, `text_layout`, `visual` must map to actual compatible generated assertion kinds. Visual ownership must match the independently pinned pixel/review policy, including host/system subjects; other native methods certify component facts. `source` requires no rule IDs and binds `subject` through config `evidence_subjects: {subject: [absolute files]}`. Component subjects belong to production roots, bridge subjects to the actual bridge, integration source subjects outside both. Host/system source claims without a verified provider remain unsupported. Source can prove only a source-review claim; computed-style/executed-integration declarations have no provider and block before SDK use.

For source claims supply an independent `source_review_store` outside production roots. The default chain writes `source-review-template.json` and pending tasks. Reviewers supply only `{version: 1, observations: [{id, observed: bool|null, reason, citations: [{path, line}]}]}`. Expectations (`true`, Boolean), responsibility and subject hashes are generated from the independent claim, not entered by the reviewer.

Bind with `python scripts/evidence_responsibility.py bind --config PROJECT.json --submission ORIGINAL_ACTUALS.json --output NEW_RECEIPT.json`. Entries are append-only and source/claim-bound. Conflicts stay unresolved, edits invalidate only the exact affected subject observations. Next default cycle and final review completion automatically import them into admission. A schema/type match is not proof that a review is correct or that a failure belongs to the component; attribution remains separate. Omitted responsibility contracts retain legacy native-component scope and cannot certify external/source/integration completeness.

`finish-native-review` also closes native-plus-source plans with no visual obligations. It reconstructs the pinned full final native packet, checks unchanged current source and completed resource cleanup, and imports required bound source observations. It does not request a dummy image review or rerun the SDK; an actual visual obligation still requires its original bound image observations, and any missing source duty still blocks acceptance.
