# BicycleServiceIntake — new native component requirement

Domain: Community bicycle workshop repair intake. Interaction structure: Grouped multi-select checklist with live work estimate and expandable handover notes.
This is an independent new design fixed before any implementation. Implement SwiftUI in alerttoast/Sources/AlertToast/BicycleServiceIntake.swift and Compose in reply/Reply/app/src/main/java/com/example/reply/ui/components/BicycleServiceIntake.kt. Keep pinned upstream source/build settings. Do not copy a reference drawing into a replacement view.

## Product behaviour

Use an eager multi-select checklist grouped as Inspection (a,b), Specialist work (c), and Care and adjustments (d,e,f). A check indicator is a visual child of each single native select button, not a nested second action. The live estimate is a separate full-width summary panel below the checklist. The handover disclosure and its expanded notes follow the estimate, then action and footer. All groups stack vertically.

Multiple available services can be selected independently. Tapping again deselects that service. The estimate is the sum of selected minutes, and summary order always follows the service list. Unavailable entries remain visible with the literal status “Unavailable”, their nonempty caller-supplied unavailableReason, and a real disabled control. available=true requires unavailableReason=""; available=false requires a nonempty reason. The component displays that reason verbatim below the item label, never invents a reason and never substitutes ordinary detail for it. Entry c is unavailable in all public examples. The model can disable any entry at replacement. A disabled interaction does not invoke a handler. The primary action is enabled exactly when there is at least one available selected item. It sends the current selected ID set without clearing the draft. Submission only requests a mechanic review; it never authorises repair or takes payment.

The disclosure is a real native button. Its visible/native label is exactly “Show handover notes” when closed and “Hide handover notes” when open. It toggles the detail block and emits one Boolean callback. The global disclosure content is exactly model.guidance and stays in its global position when choices change. Its body is intentionally hidden when collapsed. Every text item required visible under the current selection/disclosure rules, including labels, visible reasons/details, notice, subtitle and footer, must remain fully readable. Missing required text must not count as correct wrapping.

The caller replaces the model in the same live component. A changed revision is authoritative: replace the selected ID set with valid available incoming initialSelectedIDs, replace all labels/availability/details, reset disclosure to initialDetailsExpanded, recompute summary and enablement, and emit no business callback. Recomposition with the same revision must preserve user state. No network, clock, random value, animation, keyboard, permission dialog or navigation is required.

## Layout and visual ownership

The component owns its full canvas, notice panel, selection treatment, action fill, typography and all internal layout. The outer host owns its background, 16-unit horizontal inset, 24-unit top inset and 600-unit scrolling viewport. The offered width is 248 or 390 units in public cases; component child width is offered width minus 32. These are native pt on iOS and requested dp on Android, subject to the pinned Paparazzi screen encoding. Do not paint the outer host to satisfy the canvas atom.

Use the palette in reference.json for the active host theme. Solid opaque colors; no gradients/shadows over measured surfaces. Canvas fills the actual component width and full content height, rounded radius12. Keep a continuous empty canvas gutter at least12 units on both sides; children never cross it. Notice and primary buttons have corner radius10 and at least16-unit internal horizontal padding. Their normalized side sampling strips (policy.json) must be solid fill, clear of glyphs/icons/borders. This is ordinary breathing room around actual content, not hidden test patches. The full canvas keeps a semantic container with its own box; never use a text leaf as the canvas.

Internal vertical spacing is12 units; section transitions20; card inset16; card gap12; title22 base native units, semibold600; body16 regular400; supporting text14. Use palette ink for text on canvas/cards/notice, and onAction for primary action text. iOS fonts scale with Dynamic Type; Compose uses sp/host fontScale. No fixed text height, line limit, ellipsis or clipping. Wrap naturally at spaces and hyphens; if one unbroken segment exceeds the available text width, break between characters while preserving every character. Grow the surrounding block for every added line. Primary control native semantic/activation box height is at least56pt/dp and grows for wrapped content. Interactive cards also have at least56-unit height. Leading/trailing placement follows native layout direction. Match layout hierarchy and specified spacing intentions in the independently drawn SVG/PNG; vector font metrics are not a native pixel baseline.

References show the expanded state as a complete scroll strip, including content beyond the600-unit host. Public P1 is ordinary light; P2 is narrow, dark, enlarged text. Support both LTR and RTL, other valid incoming data, arbitrary item label lengths, all item availability combinations and incoming valid selections under these same rules. Full-page content is eager, without an internal ScrollView/LazyColumn. The host supplies scrolling. Do not shrink content to fit600.

## Selected ledger and limits

Fourteen independent rules, seven selected states per case. The contract fixes the exact original route and all98 cells/platform/case. Baseline, expanded and submitted are full-content sweeps. Other states observe selected targets. Wrapping and overlap are separate source-backed Boolean questions selected only for full sweeps; their target-only state cells are explicitly N/A for selected-scope reasons. Full-brief behaviour still applies there. Incomplete/fragmented native coverage stays U: a footer or bottom sentinel alone never proves the entire component. Missing or ambiguous boxes, unsuitable color support and unavailable mappings stay U.

Callbacks apply only after demonstrated successful native activation, or after the explicitly advancing caller replacement. Blocked disabled observations are not successful callback stimuli. The locked-disabled rule independently assesses enablement. Selected values/summary/enablement are current business facts, not callback proxies.

The ledger deliberately does not numerically certify every spacing, card dimension, body font size/ink, group heading, secondary choice callback, deselection path, idempotent reselect, every intermediate state, accessibility pronunciation/order, physical touch hit area, parent app navigation/lifecycle or arbitrary data not in P1/P2. Also outside this selected ledger are grouping, estimate panel placement and deselecting one item while preserving others; selected-background treatment, every unsampled canvas region and remaining typography hierarchy. Wrapping/overlap atoms cannot certify these features. Those remain full brief requirements outside this selected denominator. Title weight is native style on Android; generic computed SwiftUI weight is unavailable, so the iOS title-native-weight cells are selected U, never a visual substitute. Geometry is native accessibility/control box only; no claim of framework padding or glyph geometry.
