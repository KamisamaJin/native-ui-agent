# Executable atomic review and shared evaluator reliability

The tested release is `candidate-v8/`; its54-file digest inventory was frozen before
any new business task existed. `baseline-v7/` preserves the exact39-file public v7
release at4db3223a. Both arms already have independent typed contracts, state
coverage, callback-dispatch preconditions and native numerical metrology. This is
an incremental tool comparison, not Skill versus no Skill.

## Exclusive executable capabilities

`review_contract.py` reconstructs every generated plan from the externally approved
design lock. An independently pinned policy gives each manual rule one method,
atomic aspect, target responsibility and source-backed Boolean proposition or
opaque rendered ARGB expectation. Its catalog generates stable review identities,
expected values, units, comparison and provenance. A reviewer submits only actual
Boolean/unknown observations, rationale and original state-frame indices. It cannot
replace an expectation, unit, target or verdict. Missing decisions remain unknown.

`native_pixels.py` resolves the actual native semantic/control box in each coherent
state frame, maps it into the original PNG, clips the approved target-local region
to the real viewport and measures dominant rendered sRGB. Sampling region, support,
minimum pixels, RGB channel tolerance and visibility scope are approved before code.
The full histogram, original PNG SHA, box/coordinate packet and sample region are
retained. It never accepts an AI-entered RGB actual or chooses pixels by similarity
to the expected value. An eligible visible frame lacking measurement blocks P;
conflicting measured values stay U. Ambiguous IDs, missing mapping, unsupported ICC,
transparency and inadequate flat-color support do not become a pass.

Canvas, notice and action fills have separate rules. The evidence concerns their
approved rendered regions, not generic computed style, every canvas pixel, glyph
geometry, framework padding or physical hit area. Native text/geometry capabilities
from v7 remain available; generic computed SwiftUI font weight/size/color remain
unsupported where no native fact exists. The selected unsupported cells stay U.

The native checker reconstructs the bound review from its original request and
original artifacts. Stripped binding or changed expected/status/rationale/evidence
is rejected. Strict state identity additionally requires caller input, process
instance, event revision, state ID and post-capture binding to agree. No stale or
cross-state frame may lend a passing fact.

## Shared infrastructure, not exclusive quality gains

`acceptance.py` checks actual native environment values, preserves authoritative
numeric/pixel results and combines two fresh, independently scoped qualitative
judgments. A qualitative disagreement stays U. A strict F is not automatically a
product defect: component-owned failures need agreed independent cause support;
host/system responsibility and observation/uncertain causes remain separate.

The Compose wire adapter names known `Ltr/Rtl` spellings explicitly. The pinned
Paparazzi host records integer native viewport, density, requested Float32 dimensions
and a versioned screen conversion. The evaluator verifies Float32 input/multiply,
integer screen truncation and serialized logical output. Requested390dp can produce
1072px and389.81818dp; this is an explicit provider conversion, not a layout epsilon.
iOS uses the actual app frame/viewport for image mapping and a fixed600pt viewport.

Two fresh claim reviewers separately assess the semantics and ORIGINAL evidence of
failure claims. Formatting/descriptor rejection does not imply a false product
alarm. Both must support an original finding; later repair success cannot backfill
credit. Exact descriptor compliance is a separate engineering statistic. Cause
clusters require agreement on member sets and confirmed association, not matching
names; uncertain associations are retained rather than invented singleton bugs.
The prospective metric functions and their9 controls were frozen before design.

Original candidate sources/plans, all own D0 raw/checks, all original reviews, all
final sources and all own FINAL public endpoints each close as a complete six-unit
cohort. Hidden values are materialized only afterward. Anonymous quality panels,
claim panels and same-source replay each close before assignment reveal. The guard
checks exact launch inputs and live source against a capsule before SDK acquisition.
This is procedural isolation on a shared filesystem, not a security sandbox.

## Cost optimization and validation

The same-source diagnostic reuses identical common D0 raw bytes. v7 native-only
checks and v8 automatic pixels both withhold qualitative submissions; no extra SDK
acquisition is needed. The main planned native corpus is108 commands (own D0/FINAL,
common D0 and common FINAL including heldout). Removing redundant paired acquisition
is shared study infrastructure; its effect must not be labeled an exclusive v8
speed gain. Pixel checks reuse original captures rather than taking extra screenshots.

The recorded resource-queue sum measures a worker's wait for the native slot/lock.
The launcher does not record a separate submission timestamp for work still waiting
inside its two-thread executor. That waiting remains included in batch envelopes
and consumer end-to-end endpoints; the lock-queue sum is not a complete isolated
account of every scheduling delay. Whole-command wall, frame telemetry and model
phase spans likewise have different scopes and must not be added as elapsed time.

115 tool tests and9 metric controls passed. Actual neutral iOS/Android hosts, two
independent neutral visual panels, and a separately authored independent native
forward probe preceded tool freeze. Current-tool offline replays preserve original
requests and raw evidence. Six pre-release bound bundles were rejected after their
generated content format changed; rebuilt bundles from unchanged requests pass.
The original neutral LazyVStack coverage failure, native screen-conversion mismatch,
rejected requests, syntax failures and all earlier attempts remain preserved.

Two preimplementation design reviews rejected the initial proposal for genuine
specification/reference/sampling ambiguities. A separate design-v2 proposal, with
unchanged selected rule/state denominators, received two fresh independent approvals.
A v1 reviewer hashed additional files via the tool gate and the designer saw truncated
hash text; neither decoded the referenced contents. Both deviations are recorded,
and final approval uses fresh restricted contexts. No product candidate existed at
that point. Design repair is shared process work, not a v8 defect detection result.

The source-submission preflight was corrected before implementation to compare known
bootstrap Gradle/Package bytes against a pristine pinned host. The earlier helper
and failed design-seal field-name attempt remain archived. Frozen tool/metric methods,
independent expected values and production candidates were not changed by these fixes.

Actual component development uses SwiftUI production code in AlertToast and Compose
production code in Reply. Bridges only decode inputs and call those APIs. iOS runs
XCUITest/Simulator; Android runs Paparazzi/Compose JVM rendering and semantic actions,
not emulator/physical touch. Stable semantic IDs/public APIs are permitted for these
new components. Arbitrary uninstrumented legacy navigation, backend integration and
full brief requirements outside the selected ledger are not established by this study.

## Scheduling, anonymity and publication limits

After complete own-D0 closure, common public D0 acquisition may overlap original
read-only review and compile-only repair on separate audit workspaces. The frozen
launcher already authorizes that public acquisition after the complete initial
source barrier, and the prospective protocol does not require later acquisition.
Its two global native resource locks remain unchanged. No anonymous quality panel
is prepared before own-FINAL closure, and no hidden acquisition is authorized before
the hidden-input gate. This schedule is recorded before the first own review and is
shared infrastructure, not an exclusive treatment effect. Historical SDK-free
regression checks also overlap initial acquisition; resource sums are not elapsed
cost and this shared-machine activity limits speed comparisons.

Quality panels receive anonymous source aliases and common-collector evidence.
The privileged orchestrating root and owner can read the assignment, and the local
root tool transcript can contain it. Fresh quality contexts do not inherit that
transcript or the assignment map. This is assessor blinding, not a double-blind or
globally secret experiment; the formal reveal gate controls the disclosed graded
publication chain.
Original-claim reviewers must inspect the unchanged original finding format and
provenance. Those formats or command paths can reveal which tool produced a claim,
even though assignment-map access is forbidden. Claim review is independently
scoped and sealed, but should not be described as guaranteed treatment-blind.

The three new contracts, fixtures, references and production APIs were independently
authored after tool freeze. T1 shares the broad workshop theme with an earlier study;
this is not a claim that every topic word is unprecedented. Historical product
implementations and hidden expected answers were outside the designer's authorized
inputs, and neither old defects nor outcome-specific product changes were supplied
to the new builders. The source, design and dispatch chain is retained for audit.

Additional closure/report/publication helpers are separate from the preimplementation
frozen executable evaluator, metric functions and nine shared adapters. They consume
sealed artifacts, render tables, enumerate failures, record auxiliary costs or verify
publication bytes; they do not supply new expected values or product verdict rules.
The SDK-free Linux CI job removes unused preinstalled Android/.NET/GHC SDK directories
before checkout to leave space for the growing immutable raw-evidence history. It
does not remove published evidence, run native SDK acquisitions or change acceptance.
This is shared publication infrastructure, not an exclusive v8 speed improvement.
`disagreements.py` is an unscored post-acquisition index of every qualitative panel
disagreement, with original opinions and D0/FINAL source/launch/state-PNG equality
diagnostics. It does not add a tie-breaker, alter a verdict or establish which
opinion is correct. Reproducibility of model interpretation remains a limitation.

## Acquisition-scope gap found during the frozen run

An audit of actual launch hashes found that own acquisitions use each original
generated plan's actions, including `after_targets` on four actions. Common
acquisitions use the sealed design package's top-level base platform action file.
The business route, fixtures and bridge agree, but that base file omits the extra
after-target observations. Its explicit full sweeps cover baseline, expanded and
submitted states. Both arms share this difference; it was not introduced after
review. The preimplementation guard checked approved bytes and own-plan conformance
but did not enforce common-route equality to the generated plan's observation
extensions. This is a shared harness observation-scope gap, not a v8 benefit.

The frozen run is retained without route replacement, extra SDK retries, new
expectations or retrospective passing evidence. Missing common observations remain
unknown. Own-to-common command timing cannot establish a collector speed gain, and
original claims must be judged against original own evidence, not merely a later
common pass. `action_scope.py` audits actual D0/FINAL public launch hashes after
reveal and emits `action-scope.json`; it does not change acceptance or metrics.
Future studies should validate common launch observation extensions against their
generated plans before any product acquisition, using unrelated generic controls.
