# Independent task delivery interface

This interface fixes file/data shapes before business requirements are chosen.
It does not prescribe a domain, a desired defect, candidate source or the answer.
Tools and metrics freeze before the designer starts. Each task receives only current
Skill documentation, this interface and the shared native host/API constraints.

Deliver THREE distinct complex component-development requirements in unrelated new
domains, with materially different interaction structures. Use SwiftUI production
files under alerttoast/Sources/AlertToast and Compose production files under
reply/Reply/app/src/main/java/com/example/reply/ui/components. Bridges must import
and call those actual public APIs, never reconstruct a tested copy. Existing pinned
upstream source/build settings remain unchanged. No deliberately defective code.

Each task folder T1/T2/T3 has public/ and private/. public contains BRIEF.md, API.md,
reference.json, independently created reference SVG plus rendered PNGs, contract.json,
design-lock.json, policy.json, bindings.json, approval.json, Bridge.swift,
ObserverBridge.kt, cases/P1 and P2. Cases contain fixtures.json and platform actions.
compiled/P1 and P2 additionally contain the same fixtures/platform action files and
compiled <platform>/plan.json/actions.json. Builders receive all public requirements,
references, APIs, policy, cases and approval; they generate their own original plans
rather than consuming compiled acceptance plans.

Use the actual generic design_contract compiler in frozen candidate-v8. All manual
rules are atomic and receive a review_contract policy with source-backed propositions,
source-backed opaque rendered colors where measurable, exact method and responsibility.
Approval records canonical design_lock_sha256, policy_sha256 and environment_sha256
per case/platform. Native styles unavailable on iOS stay explicit selected U, not a
visual pass disguised as computed typography/color. Public expected values, units,
comparisons/tolerances, selected states and original action route are independent.
A rule/state/platform may be N/A only for a concrete independently fixed reason.

There should be a manageable selected denominator with substantive business/current
and transition assertions, geometry/native style where supported, multiple rendered
color atoms including component-owned canvas, and separate visual wrapping/overlap
or hierarchy atoms. Explicitly list full-brief requirements outside the selected
ledger. Do not make the UI trivial to suit the observer or infer unsupported methods.
Fix sampling regions according to the approved role geometry; do not assume a native
text box contains only background. Inconclusive color evidence must stay U. Specify
component versus surrounding host responsibility in BRIEF/API as well as policy.

Use two public cases (ordinary; narrow/dark/large text) and one private heldout H1
with new data/combinations within the public rules. Select6-8 meaningful states per
case with real native tap/caller-update/sweep actions, within40 actions. Full-content
sweeps and selected target checkpoints must match the approved scope. Initial/final
are reserved native state IDs. Callbacks must follow successful native dispatch or
caller replacement; disabled actions are not successful callback stimuli.

Host constraints: iOS iPhone17 Simulator26.5, Xcode app, explicit offered width160-402pt
and a fixed600pt viewport. Android pinned Paparazzi/Compose JVM host with density2.75,
explicit requested width/viewportHeight600dp, fontScale and native LayoutDirection.
The environment contract uses theme/direction/dimensions and dynamic_type on iOS,
font_scale on Android; Android explicitly uses the versioned screen-config dimension
encoding in the Skill. This is not an Android emulator or physical touch test.
The outer test host may have its own background; a component-owned canvas must be
painted by the production component and observed within its intended native box.
Stable semantic IDs/public APIs are allowed for these new components; this study is
not arbitrary uninstrumented legacy-screen fuzzy targeting.

Store each case's environment.<platform>.json and canonical digests in approval.
Private H1 has its own preimplementation approved source/contract lock/policy and
compiled/H1 fixtures/plan/actions/environment, with the SAME public rule identities
and no new requirements. Keep all heldout values private until public FINAL seals.

Record actual design started/finished times, all files/digests and a write-once task
seal; then whole-cohort seal. A separate fresh design reviewer checks brief, references,
typed values, actions, ownership, applicability, sampling semantics and schemas before
any candidate implementation. Revisions remain new preserved directories, never edits
to an already sealed proposal. Tools do not change to accommodate a new business case.
