# Prospective interpretation and separation of benefits

Use generic metrics.py frozen before design. True-alarm counts depend on two
independent judgments of ORIGINAL claims and state-scoped original evidence, with
supported source/contract mapping; neither later repair success nor a common bug
allows retrospective expansion of an original observation to new states/aspects.
The main semantic metric can recognize an explicitly supported original observation
whose formatting differs, only when both independent judges agree. Raw claims are
never edited. Exact expected/unit/descriptor compliance is separately reported.
Unsupported semantic mapping stays U. Schema errors/rejected requests are engineering
failures, not automatically false product alarms. Supported FP needs both judges'
explicit original-evidence-negative determination. Successful observations and typed
failure duplicates stay outside the unique alarm denominator.

Automated native properties/events/geometry and automatically sampled original color
facts are machine evidence. Human/AI Boolean visual propositions are manual evidence.
Both category and union are reported. The old arm may use all its frozen tools and
approved atomic references; it is not deliberately denied information or forced to
write a malformed report. The new arm's executable binding is the treatment.

Strict F, independent product/infrastructure/observation/uncertain cause, unsupported
U, independently justified N/A and unasserted brief scope are distinct. A recorded
color/geometry contradiction is not automatically a production defect. Component
failures need agreed cause support; component/host/system ownership is fixed before
implementation. Qualitative status disagreements become U; native/pixel facts remain
unchanged with raw opinions attached. Same-cause cluster names need not match, but
membership sets must agree and both reviewers must mark the grouping confirmed.
Uncertain clustering is reported without inventing independent singleton bug counts.
Zero known product/cluster denominators remain N/A.

Common acceptance uses the SAME frozen evaluator and native collector on both
anonymous source groups. Provider-specific environment compatibility, dual panels,
source/schema/evidence checks and orchestration are SHARED reliability infrastructure.
They cannot be credited as exclusive v8 quality or speed improvements.

Same-source diagnostic uses identical common D0 raw bytes: old v7 native checks
without injected visual answers versus v8 automatic pixel checks with qualitative
observations withheld. It measures automation over already captured evidence, not
additional native observation, full visual acceptance or independent development
quality. Actual review compute/resources are retained; no new SDK acquisition is
needed. Native collector viewport metadata is separately verified as an explicit
provider wire change; action/callback/scroll behavior is not intentionally altered.

Primary latency ends at the unit's own FINAL public raw-and-automatic-check endpoint,
including waiting for cohort barriers and other raw corpora. Also report raw seal,
all-six closure, model phase wall, native command and review compute sums, actual
queues, common acceptance, both judging stages and complete experiment to reveal.
Publication/CI is separate. Shared caches/order/hardware and only three task pairs
limit speed/quality causality. Agreement between two AI reviewers is not human gold;
report disputed/unknown cases and bounds, rather than claiming an objective error
rate where the evidence cannot determine it.
