# Independent design-v1 delivery

Design began at2026-10-22T01:14:41Z, after the tools seal. No candidate production source, historical business case, private assignment or implementation screenshot was inspected. Only DESIGN-INTERFACE, frozen candidate-v8 Skill documentation, generic observer/template APIs, example schemas and generic compiler/evaluator source were used. No native SDK, Gradle, Xcode, simulator or production component was run or authored. The Python renderer converts independently authored SVGs into PNGs with MuPDF.

T1 introduces makerspace station booking with a responsive single-select time grid. T2 introduces river monitoring incident triage with a chronological timeline and an inline selected dossier. T3 introduces bicycle workshop repair intake with a grouped multiselect checklist and a live work estimate. Each public requirement describes production SwiftUI/Compose files and actual public APIs. Bridges decode models and forward callbacks only; component state, views, semantic IDs and all styles belong in future production code.

Only each T*/public directory is builder-facing. Builders receive BRIEF/API, references, cases, policy, bindings, approval and bridges. Do not give builders public/compiled: those are evaluator acceptance artifacts; builders generate their own original plans. T*/private, root private/, all authoring-attempts, authoring scripts and root internal records stay private to design/review staff. Never publish H1 values or rendered H1 imagery before all public FINAL implementation seals. H1 has its own lock/policy/approval and the same14 public rule identities and methods; it adds no requirement.

Every case selects seven states ×14 rules =98 ledger cells/platform:81 required and17 concrete N/A. The14 atoms cover current summary, first selection, locked enablement, primary enablement, disclosure label, successful callback, replacement quietness, actual control box height, native title weight, three separate opaque rendered colors including component canvas, visual wrapping, and visual overlap. iOS native title weight is explicitly selected U because public AX exposes no computed SwiftUI weight. Full-brief requirements outside this denominator are listed in each BRIEF. Compilation and SHA identity do not certify design quality; a new independent design reviewer still needs to check the proposal.

Original actions are cases/<case>/actions.<platform>.json. Each contract fixes those exact logical routes and states. Compiler-enriched after_targets bind current native facts; full sweeps are separate selected checkpoints. The expanded and submitted states use stimulus_action for the earlier real tap, so callback checks never use the later empty sweep delta. Checkpoint maps fix input revisions/hashes, action indices, observation scope and stimulus index. A held disabled tap is deliberately not a callback test. Use replay_contract.py with an output folder that does not exist to generate exactly the selected approved route and ledger. The same tool can compile H1 only inside private evaluation.

Example evaluator command from the repository root:

    python3 validation/atomic-forward/design-v1/replay_contract.py --task T1 --case P1 --platform ios --output /absolute/new-evaluator-output

Host constraints learned from the frozen APIs: iOS offers width160–402pt in this study but its native viewport height is fixed600pt. Both hosts inset the child16 native units per side and24 at the top. Requested width is not the component child width. Android is the pinned Paparazzi/Compose JVM host atdensity2.75, not an emulator. Android environment dimensions explicitly use paparazzi-float32-screen-config-v1; requested Float32 dp become truncated screen pixels and then serialized native Float32 dp. Every case/platform environment has a canonical SHA in its own approval. The real acceptance.environment parser was called with no observation only to check schema; it correctly returns U. Native environment validity still requires actual future evidence.

Schema limits: native geometry is accessibility/control bounds, never padding or glyph metrics. Unsupported layout boxes/styles stay U. Rules have exact source-backed typed values and explicit comparisons; the primary action native control height is >=56pt/dp with no invented tolerance. Manual policy allows one aspect/method per rule and fixes component ownership. Color regions are reserved ordinary empty side gutters of actual panels/buttons/canvas, never inferred from a text box. Insufficient support/mapping/conflicts stay U. Whole-content wrapping/overlap pass only with exact-state complete overlapping native intervals; a visible footer alone is insufficient.

Initial drafts and every revision script are preserved in authoring-attempts. Before the final task/cohort seals, independent reference QA corrected row heights/alignment/checkbox prefix handling, the explicit sweep bound key was corrected to the frozen API's max_steps, and a Swift signature documentation-order typo was aligned with the unchanged authoritative Bridge.swift. No locked typed value, rule, method, original action semantics or frozen tool was changed after contract locking. Further proposal revisions must use a new directory and new seals.
