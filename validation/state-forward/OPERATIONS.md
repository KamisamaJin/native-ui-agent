# Prospective operations (before builder source)

Both Skill arms use the same default agent settings, public design, pinned
upstreams, dependency bootstrap, hardware and native host. Each acquisition has
one iOS slot and one Android slot. Acquisitions for distinct arms may overlap on
this one Mac; each owns a separate simulator and Gradle checkout. Actual start,
end, command walls and contention/waiting remain in costs, without statistical
performance or model-quality causality claims.

The fixed v5 observer is the common acquisition tool for independent acceptance
on both D0 and FINAL sources. Its input/actions/targets are translated from the
independent frozen acceptance, separately from each builder's own public check
plan. This common infrastructure is not counted as a v5 treatment improvement.
Same-source D0 pairs compare v4/v5 collectors on identical common inputs; the
already acquired v5 common D0 side may be reused byte-for-byte for that pair.
The paired v4 side is a separate real native acquisition.

Each builder seals its own translated check plans before rendered feedback.
Own review uses that arm's actual observer and own selected targets/expectations,
not hidden or independent acceptance answers. Both D0 sources and own corpora
must seal before either agent receives review feedback. Original self-review
and typed-check reports seal before one repair. Both FINAL sources must seal
before native held-out inputs. A fresh own FINAL corpus is the continuous
implementation-to-own-final endpoint; common grading and same-source pairs add
experiment costs, recorded separately.

Native acquisition failure is retained with its exact source/input/logs; it is
never replaced silently or promoted into a semantic business F. Admin retries
need a recorded generic reason and keep the original failed attempt. A grading
policy repair must precede outcomes or be reported as an explicit common
evaluation amendment, never a tool-arm gain.

The independent evaluator receives anonymous D0, FINAL, self-review, paired-D0
batches in that order. Both grades in each batch must seal before the next
delivery and formal assignment release. Recognizable source/output formats and
shared filesystem mean procedural blindness, not secure isolation. Original
typed-native failed assertion rows receive equal detection credit in both arms,
even when v4 lacks the new machine_findings convenience field.
