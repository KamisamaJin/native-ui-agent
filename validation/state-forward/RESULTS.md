# v5：覆盖改善，代码质量优势仍未证实

本轮把动作后多目标观测、同输入/进程/事件的证据合并，以及声明状态×检查方面的编译做成可执行能力。冻结前完成中性组件和独立通用验证，再由独立上下文设计全新的 **Print Batch Approval**。比较两份独立生成的组件实现：冻结 Skill v4 与 v5；两组都使用 Skill，不是有/无 Skill 对照。

同源码采集器配对证实了覆盖收益：运行时未评估 **54.39%→40.85%**，新增 **2424** 行证据，没有丢失或已裁定冲突。但配对命令资源时间 **365.634→734.914秒，+101.00%**。开发结果没有证实质量优势：v5 实现漏检46条原生字体规则，最后仍有74条字体F；两组都没有已评估的自然业务F，业务漏检率为N/A。

完整复算见 [TABLES.md](TABLES.md)、[result-summary.json](result-summary.json)、[全部配对变化行](paired-changes.json)。原始失败、未裁定项和未评估行没有删除。

## 独立设计与封存顺序

需求包括多作业选择、彩色/黑白单价、按每份副本向上取整的双面纸张计费、仅非空时收取优先费但保留空态优先标志、预算门控、明细展开、精确事件载荷，以及完整模型替换重置。四个公共场景、两个隐藏场景覆盖320/390宽、浅深色、1/1.2字号比例、RTL与长内容。每场景最多两个模型、八个非滚动动作和两个完整滚动检查点。

独立设计先固定[业务/视觉要求](design/public/BRIEF.md)、[公共API](design/public/API.md)、[参考SVG](design/public/reference.svg)和完整验收账本，再由两个相同默认模型设置的独立 agent 实现。源码落在固定 Reply / AlertToast 上游的真实生产模块中，薄宿主导入并调用生产组件。

固定分母为37个逻辑状态、74个平台状态、14420个P/F/U行及896个显式N/A行。D0主结果仅使用实际交付的公共运行时8948行；FINAL使用全部六场景的14324运行时行。源/API10行、输入24行、刺激执行62行分开统计。隐藏场景D0缺证据仍保留U，但不拿它们放大首版漏检分母。

两份D0源码和自身语料先封存；各自原始只读审查先于唯一一次修复；两份FINAL源码先于隐藏原生输入。自身FINAL按原计划重新采集，原始计划和检查器未改。独立评估按共同D0→共同FINAL→原始自查匹配→同源码配对依次收到双组数据，每批两份评分先封存才交付下一批。[正式揭盲记录](private/ASSIGNMENT-RELEASE.json)晚于全部四阶段封存：`source-a / unit-93485d = v5`，`source-b / unit-fb632e = v4`。

配对原始采集在共同采集完成后与较早的评估工作重叠，结果仍等自查匹配封存才交付；[排程记录](private/paired-acquisition-scheduling.json)保留实际时间。原始格式和来源路径可能暴露版本，共享文件系统也不是安全隔离。主D0/FINAL评分在收到自查格式之前已经封存；本轮采用程序性盲法，不能声称完全双盲。

原子行不是独立bug数。v5的46个视觉F来自同一状态标记布局问题，23个状态各涉及可读性与裁切两方面；修复后这些视觉行通过，另有7个覆盖行恢复通过。两类Android字体错误各影响23个公共状态，在14个隐藏状态仍分别失败，最终共74F。

两组的iOS priority原始AX高度28都被识别为F。修复后实际变为48，但冻结规则给派生尺寸±2pt不确定性，区间跨越最小48，因此各23个原始F变成U。这是实际几何改善，尚非严格验证通过；不能把F→U计入修复成功，也不能把它解读为源码完全没有改善。物理点击区域仍无OS检查能力，全部1184行U。

运行时业务当前事实与成功刺激后的行为分开。FINAL每组有52个已评估回调区间P、10个禁用/未建立刺激的回调U；iOS完整转换26P/5U，Android31个转换因未导出展开布尔值等原因保持U。没有业务F不代表业务全部通过，更不能得出零漏检能力。

## 为什么自查漏了字体错误

v5原始计划把摘要字号写成14、余额字重写成400，实际生产代码也使用这些值；独立设计要求摘要12、余额semibold。原生观察器已经提供实际字体数据，但错误的自测预期让它们通过了自查。

状态矩阵只能保证声明过的检查方面覆盖声明过的状态，不能证明预期值正确。笼统引用整个brief也不能建立某个数值的正确来源。本轮没有在看到这个结果后修改工具、业务源码或验收重算；[原因分析](ANALYSIS.md)讨论独立类型化设计契约与原始检查噪声这个通用缺口。

## 误报、未知主张与诊断重复

首次实际报告+手工主张的条件FDR为：v4 **137/(46+137)=74.86%**，v5 **114/(46+114)=71.25%**；另有376/415条不确定或未映射主张。将这些未知主张分别全部算真/算假，两端范围为v4 **24.51%–91.77%**、v5 **19.83%–92.00%**，不能用条件比例的小差异宣称误报显著改善。

手工单独确认FDR均为0，但另有14/6项未知，而且v5手工审图仍漏了原生字体错误。两组原始失败断言522/546条全部具有同等匹配资格；v4无需`machine_findings`字段。旧组492条实际诊断重跑另列，含重跑条件FDR为77.96%，唯一检出数不变。U、限制和通过的评论保留为非正向账本。

浮点精确等值、回调JSON表达、overflow原生标志、外部宿主画布和超出冻结视觉措辞的RTL精确字符顺序分别裁定。原生overflow不直接等于可见裁切；不确定主张未被删掉或强判为误报。缺完整TN集合，经典FP/(FP+TN)不可得。[原始主张与匹配](evaluation/selfreview/SUMMARY.json)保留按来源、类别、范围、首次/诊断的全部面板。

## 共同修正、完整性与范围

宿主/桥接适配、完整参考图、实际动作收据映射及评估器字段修正都是共同基础设施。Android语义尺寸字段的v2/v3重放在D0各改变368行来源记录、FINAL各592行，**没有实际值或分数变化**。回调成功派发门控继承v4，函数AST未改；多目标观测不能延长即时回调区间。

完成88次计划业务采集，保留1891个快照记录和3次非零退出；另有冻结前通用原生验证。[失败记录](FAILURES.md)、[所有前后初始视口](GALLERY.md)、[基础设施归因](INFRASTRUCTURE.md)、[复现](REPRODUCE.md)均公开。CI验证封存证据及统计，不表示组件全通过。隐藏场景现已公开，只适合复现，不能再用于下一轮新盲测。

单任务单次/每臂、相关平台、AI视觉裁定、共享硬件及可识别输出格式限制了结论。本轮验证新生产组件与明确公共selector、薄宿主，未验证任意不改造旧页面的模糊定位、全应用导航、后端或真实系统物理触摸。iOS数值字体、内部padding/颜色等观测缺口继续保留U。结果支持“工具获得更多证据并付出更多采集成本”，不支持“native PR质量已普遍改善”。
