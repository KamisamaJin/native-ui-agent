# Executable changes validated before new product code

`requirement_routes.py` binds an independently authored obligation index to exact
state/rule cells. It separates missing contract routes, environment repair,
missing evidence, oracle disagreement, source diagnosis and capability/locator
investigation. Admission requires all MUSTs, a verified full source-bound capture
and actual environment P. A partial receipt cannot be relabelled full by a CLI flag.
The independent final forward test found that intentionally omitted feedback states
were entering the locator backlog. Before business design, routing gained exact
manifest reconstruction and explicit deferral of unrequested U rows. Genuine
supported failures remain actionable. Previous reports and the failed unit attempt
remain preserved; no specific product label/color/font enters the routing code.

`execution_plan.py` rebuilds business actions, after-targets, observation scope and
required coverage from one independent parent plan. It requires independently
sealed bridge/fixture launch approval. Targeted feedback retains the original
business-action prefix and indices. The runner fingerprints actual production
sources before/after SDK execution, verifies actual coverage/environment, pins
original native images and records the original automatic report. Each request
starts a fresh native acquisition; compilation can reuse content-addressed output.

`retest_plan.py` maps original failed checks to approved obligations and regression
dependencies. Its measured mode derives changed files from actual source maps,
rejecting report/root substitution or unchanged source. Approved visual actuals
can be rebound and recomputed against original native pixels/contract, without
substituting an arbitrary status report. A synthetic unit control exercises a
visual failure and changed source, and rejects an altered original image. No
live component defect was inserted to manufacture a successful repair. The
neutral actual source stayed unchanged, so its real unchanged-source retest
rejection remains a negative result rather than an invented repair success.

The optional iOS coalesced executor uses fresh AX facts from each captured packet
for sweep membership and reuses that same input/event epoch's complete sweep for
its target observations. It removes auxiliary unrequested full scans. Real native
activation, successful dispatch gates, immediate-after frames, settle waits,
source/input/process/event bindings and overlapping interval requirements remain
in force. Native observer/ios_observe bytes match between the paired timing
candidate and final release. Later Python receipt/routing glue was validated in
fresh targeted runs before release freeze.

The eight paired neutral runs use identical component code, fixture inputs and
required state/target/callback coverage. All have 54 supported native passes and
12 initially unassessed visual rows; no extra U or known native conflict. Reversed
order repeats, cache/boot/native/export times, original logs and independent image
reviews remain available. Both strategies expose the same natural disabled-palette
visual problem; no source/expected patch was used to improve the timing result.
The targeted runs intentionally cover fewer states and are not counted as another
equal-full-coverage speed result.

The shipping Skill has 132 passing unit controls, including the original 115.
The neutral design's legacy compound visual clauses lack the later atomic policy
artifacts, so the independent reviewers correctly keep that workflow limitation.
The new product designs must provide independently approved atomic policies before
implementation. Controlled-host evidence establishes only observed native facts
and approved pixel/visual propositions; generic computed SwiftUI styles, physical
hit regions and complete product-page integration are not certified.

Common services, source/host guards, complete cohort barriers, consumer final-check
service and independent evaluator are shared by both repair arms. Only the assigned
frozen Skill's decision/routing/retest capabilities differ. These benefits must be
reported separately. All methods and templates close in METHODS-RELEASE before the
new business designs; later transport/report scripts preserve those criteria.
In particular, both conditions receive the v9 unified execution backend and the
same final MUST-ledger admission service. The blind comparison estimates the
additional agent-facing decision workflow over that common infrastructure; it
does not isolate the whole v9 bundle against an unmodified old execution stack.

The source-only supplement was separately fixed before business source existed.
During T1 self-review it exposed a common combined-workspace setup omission:
contracts use upstream-relative `Sources/` and `app/`, while real files live under
`alerttoast/` and `reply/Reply/`. One participant installed aliases; the other
preserved a blocked source review. Root then provided the same explicit directory
views to both conditions with `source_views.py`, before T2 repair handoff. Original
failures remain, all production hashes and existing gates stayed identical, and
the resulting source catalog equals the earlier baseline catalog byte-for-byte.
No frozen tool, design, expected value or native packet changed. Relative links and
their literal Git targets are published with portable capsules. This is shared
infrastructure recovery with actual observed cost, not a v9 product repair benefit.
