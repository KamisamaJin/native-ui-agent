# v9 decision and feedback forward study

This prospective record precedes changes to the tested tools, neutral native
comparison, new product designs and initial PRs. Baseline is the exact 54-file v8
Skill at 150eb304. Old publications, failures and grades remain byte-exact.

Implement executable requirement coverage/discovery routing, one source-backed
execution manifest, targeted feedback planning and optional iOS observation
coalescing. Expectations, units, tolerances, real dispatch prerequisites and
source/process/input/event/state binding stay strict. Unknown evidence is not P.
No global component instrumentation or new computed SwiftUI-style claim.

First use unrelated neutral native hosts and schema controls. Freeze their source,
fixtures, action/coverage contract and expected tests before acquisition. Compare
v8 and candidate on the SAME source, inputs and required state/target/callback
coverage. Two native environments, two paired repetitions with reversed order;
record cold/warm build/cache state, per-stage time, gestures/queries/frames and all
failures. A speed result requires no loss of required coverage, no supported
status conflict, successful real dispatch where required, and no extra U. Image
bytes need not match between native acquisitions. Preserve failed attempts; fix
only general engineering issues on neutral cases before freezing the release.
An independent minimum-context forward test must precede product design.

After tool and common evaluator/metric freeze, independently design TWO new
complex UI tasks, each with both platforms, public ordinary and narrow/large-text
cases plus heldout caller data/direction. No previous product implementation,
failure or hidden answer is an authorized design input. Independent design review
must resolve all MUST obligations to an approved automated or explicit visual
verification route before implementation. Record advisory/unsupported scope.

For each task a separate builder produces ONE initial dual-platform PR, using only
the approved public API/design and compile-only checks, at most25min. No artificial
defect injection or requirement/expected edits. Seal BOTH initial PRs before D0
acquisition. Copy the SAME initial source bytes and D0 evidence to both repair
conditions. If there are no confirmed natural defects, repair/miss denominators
are N/A; do not seed faults or silently replace a task to obtain a favorable result.

Old/new Skill repair conditions share the validated optimized execution service,
toolchain, immutable design, initial sources and hardware-slot policy. Both can
request approved case/state feedback through the same service; v9 additionally
has executable routing/planning. Thus native executor savings are a separately
measured SHARED infrastructure effect, not an exclusive blind repair benefit.
Assignment/order is committed before dispatch. Fresh scoped contexts cannot read
the map, other arms or later judgments. The orchestrator is privileged: this is
assessor isolation, not a security sandbox or double-blind human experiment.

Each arm receives a20min wall editing/review/feedback budget, up to TWO inner native
feedback requests, early finish allowed. Native waits and compilation count; an
in-flight request drains and its overrun remains recorded. Only approved production
component paths may change. Every request seals its exact source version and
checks locked bridge/fixtures/plan/tool hashes before SDK execution. No direct
unlogged SDK acquisition. Targeted feedback declares its incomplete scope and
cannot claim full PR acceptance. No evidence reuse across changed code or state.

Each arm seals final source independently; then its own full public final execution
and automatic checks run as soon as its slot is ready. Editing is over. The primary
endpoint is initial-PR handoff to that arm's final PUBLIC verification result,
including its compilation/native/check/queue time. No artificial all-arm barrier
is added to that consumer endpoint. The shared initial-authoring time is reported
separately and identically for both conditions. Acceptance latency is defined only
for an actually accepted PR; failed/unverified gates are not timed as accepted.

ALL final sources/public endpoints close before external quality judging or hidden
inputs. Public independent grading reuses the exact own-final full-plan bytes from
the same shared collector; do not reacquire a different 'common' route. Hidden
acquisition follows the complete cohort seal. Two fresh independently scoped
quality contexts per task/stage, and two fresh original-claim/cause reviewers,
retain disagreement as U. Complete each panel before delivering the next. All
grades and original-claim judgments seal before formal assignment reveal. No later
repair, third-judge override or expectation/denominator rewrite.

Primary quality: final confirmed MUST product violations/escaped cause clusters,
new confirmed regressions, D0 product F->FINAL P/F/U, equal-initial-population
repair/miss rates, unresolved MUST obligations and release disposition. Repeated
states are manifestations, not independent bugs. Final U is not fixed. Semantically
supported original claims require original evidence; schema errors/unmapped
findings are not automatically FP. Classical FPR N/A without a complete TN universe.
AI consensus is not human gold. Preserve all source versions, failures and limits.

Costs: handoff->verification result per arm, actual accepted/not accepted outcome,
first actionable evidence and first verified repair when observed, per-request
native stages, model/compile spans, queue, full-final checks, initial authoring,
neutral validation, independent grading, preregistration->reveal and publication/CI
separately. Resource sums can overlap. Two task pairs do not support a stable P90
or causal population claim; report raw paired values/ranges. Tokens/money N/A unless
actually supplied by the host. Match cache/order and isolate mandatory coverage.
