# Minimum iOS compatibility verification

The original iOS 14 requirement remains mandatory. The source index contains `ios14-api-availability` against the actual production Swift file, in addition to exact exported API declarations. Review every unguarded SwiftUI/Foundation/standard-library API for iOS 14 availability and verify any newer API has an availability guard and compatible fallback. Unknown availability blocks the source gate; the iOS-17 observer build cannot establish this clause.

After implementation, run the exact future clean package build route in `compatibility.json` against the actual final AlertToast checkout with deployment target 14.0. Use a fresh derived-data/evidence directory, retain command, Xcode/SDK identity, actual deployment build settings, full log/exit code, and before/after final production SHA matching the independent source audit/native capture. Do not reuse a higher-deployment observer build as this evidence. This is a separate compatibility validation requirement shared by both conditions, not a change to the frozen runtime evaluator or metrics. No compatibility build is executed or claimed during design. It establishes compile-time API/deployment compatibility, not an iOS-14 screenshot, physical hit region, or runtime behavior result.
