# Native UI Agent

在用户已有的 coding agent 中运行本 Skill。由 agent 读图、推理和修改源码；随附 runner 执行已确认的渲染命令、保存证据并汇总检查。runner 本身不调用模型，也不自动生成原生测试宿主。

## 接入实际工程

先确认本次仓库、平台、UI 框架、组件入口、构建版本和已有渲染能力。只读目标平台的 [平台适配](references/platforms.md)。保留旧项目的框架和部署版本，优先复用同类组件、主题、字体、资源及现有测试。

若与工作区的 mobile-native-delivery 一起使用，由 delivery 负责业务路径、数据和生命周期验收，本 Skill 负责视觉实现与修正；本 Skill 也可以独立使用。

按本次改动定位组件，不要求全项目登记组件或批量添加业务 View ID。结合变更文件、调用位置、页面文案和实际渲染验证目标。访问受限或依赖复杂时，从真实父容器或实际页面创建，明确测试范围。

## 固定期望与最小状态集

从 testcase、设计、既有已批准基准和项目先例提取期望，并保留出处。新设计参考与既有界面回归分别记录。把推断标注为假设；无法确定期望时保留待确认项。

新增 UI 要在实现前固定独立设计参考和验收标准。线框图用于结构、层级及明确标注的样式意图；不要拿实现后的截图当作其自身的设计参考，也不要把不同渲染器的线框字体差异当成像素回归。能从原生布局/文字结果获得的关键数值单独断言；图中明确的颜色或样式细节也需逐项核对。

选择本次相关的普通内容、长文本、缺省内容、主题、字体或尺寸场景，不做所有维度的笛卡尔积。每份 profile 对应一个平台、组件状态和一张实际图片。两端分别渲染、分别比较参考图，共享业务规则。

按 [执行与证据协议](references/protocol.md)为项目生成真实 profile。随附 [Android 示例](assets/profile.example.json)和 [iOS 示例](assets/profile.ios.example.json)展示字段结构，需要替换为当前项目确认的命令、路径和期望。必需检查在实现前固定；改变检查时保留需求依据。

## 实现并取得反馈

1. 先记录相关构建和原有视觉基线。
2. 在生产组件上做本次需要的改动，复用已有样式与布局方式。
3. 复用或生成薄的测试宿主，直接调用生产组件，注入确定性数据和主题。
4. 用 scripts/ui_loop.py capture 执行 profile，读取 capture.json、原生测试报告及实际图片。进程成功和 captured 都不是样式通过。
5. 阅读完整图片和必要的局部裁剪。结合组件调用、布局数据和测量证据定位问题。
6. 用 scripts/ui_loop.py review 执行数值、像素检查并合并 agent 的视觉 findings，输出 report.json。

测试宿主需要调用真实实现。对网络、时间、随机数、远程图片和动画使用工程已有的可控制入口。复制一份近似 UI 会使测试失去与生产组件的联系。

数值结论使用测试宿主产生的测量证据。截图只能支持视觉判断，不能证明所有实际字号、颜色或 padding 属性。UIKit/View 属性、几何边界、文字绘制边界分别说明。SwiftUI/Compose 无法读取的属性保留 needs_review，不由 agent 填造数值。

## 按证据修正

用户要求实现或修复时，记录“失败场景 → 证据 → 源码位置 → 原因假设 → 最小修正”，修正后重新 capture 和 review。纯测试请求输出发现，不自动修改生产代码。

首版达标时直接报告通过，不人为插入错误来制造修复案例。后续发现首轮视觉判断遗漏时保留其局限、追加有依据的审查，不能只展示最终通过结果。

通常先检查容器尺寸和约束，再检查字体换行、图标及颜色细节。依据实际原因选择修改位置，不为消除差异随意增加偏移量。

一次工作默认最多进行 3 轮视觉修正；同一失败没有改善时重新检查定位、状态和期望。保留当前最好的可解释结果及未解决证据，不继续无目标重试。这个限额可由用户或项目约定调整。

每轮使用新的输出目录。代码改变后，旧 capture 不能用于声明新代码通过。正式基准独立保存，capture/review 不更新它；新结果只有来自独立预期或已批准基准的支持才能成为通过依据。

## 在页面中复验并交付

组件级检查通过后，用项目已有 UI/E2E 工具在实际页面检查本次相关的父容器、滚动、safe area、键盘、点击与状态切换。由截图工具验证的部分和由模拟器/设备验证的部分分别记录。

输出修改位置、原生构建/测试执行情况、场景清单、逐项结论、实际图与参考图/差异图，以及尚未验证的内容。

报告状态为 passed、failed、needs_reference、needs_review 或 error。视觉 findings 是模型判断；数值和像素结果是相应证据范围内的自动检查。不得把缺少测试、组件未执行、环境故障或缺少参考归入通过。
