# Current-host generic replay runtime admission

This is a new runtime admission, separate from the frozen historical Darwin inventory. No historical inventory, backend, worker, JSON input or expected result is rewritten. The existing actual-data ALL30 CAUSE gate and unsupported source-domain/source-responsibility boundaries remain unchanged. No actual study, grade, alarm, mapping, SDK, Git or network operation is part of this tool.

Run this exact command on Linux with Python 3.11 and **Pillow 11.3.0 already installed**:

```sh
bash validation/pooled-forward/publication-runtime-admission/ci-python311.sh
```

The command creates a fresh owned `HOST/ci-python311.*/admission` directory. It does not install dependencies, reuse a historical runtime, skip controls or overwrite a prior admission. Root can retain that directory as the CI artifact. A missing/wrong Pillow distribution, another Python version, a non-Linux host, a pin mismatch or a required-control failure produces a failed result and a nonzero exit.

The direct command is also available:

```sh
python3.11 -B validation/pooled-forward/publication-runtime-admission/admit_runtime.py \
  --target linux-py311 \
  --output validation/pooled-forward/publication-runtime-admission/HOST/UNIQUE-CI-RUN
```

For an honestly labeled local mechanism check, use `--target current` with a fresh output. The author local result is **Darwin arm64 / Python 3.9.6 / Pillow 11.3.0**, not a Linux execution. A separate real Darwin invocation with `--target linux-py311` is retained as an expected rejection. Linux/Python 3.11 qualification remains for root's CI execution and independent preflight.

## What is qualified

The tool verifies `SOURCE-INVENTORY.json` against a fixed code constant. That inventory binds exact frozen A/B backend SHA references, the unchanged historical worker, the unchanged 23 generic replay tests, generic assets, the historical inventory/freeze bytes, and a fixed historical generic evidence manifest.

It creates a **NEW** `owned/CODE-INVENTORY.json` with the current interpreter bytes/version, current Pillow 11.3.0 package bytes, wheel metadata and every wheel-owned support-library byte. Installed `WHEEL` and `RECORD` metadata are required. Bytecode is excluded; unrecorded package files, aliases and missing wheel files fail. A/B backend sources still match `BASELINE-COMMON-FREEZE-6` and `CANDIDATE-FREEZE-10` exactly.

Linux wheels can place shared dependencies in a sibling directory such as `pillow.libs`. The separately labeled `replay_current_host.py` revision adds only explicit support-file inventory/layout verification and appends those verified files to the **unchanged worker's** inventory. Its exact diff is retained. No backend evaluator, expected value, actual value, image proof, source-domain rule or worker check is changed. On Linux the copied current-host `.so` libraries and their original relative layout are used; historical Darwin `.dylib` files are never selected as a Linux runtime.

Qualification requires all of the following, without a skip flag:

- Six source/host/version/support-library controls, including corruption and missing-support rejection.
- Both frozen backends matching the fixed historical generic catalog, bound manual evidence and native report exactly. The two original PNGs, contracts, observations, submissions and expected results are copied raw from the earlier independently frozen synthetic author run; expectations are not generated by the new runtime.
- The same unchanged 23 generic replay/corruption/epoch/U controls, including a real Resolver restore with absent original data keys.

The result cites the fixed golden manifest, source inventory, new runtime inventory, code snapshots, full logs and exact control-result pins. It qualifies **only this fixed generic evidence and those controls on the recorded host**. It is not approval of arbitrary data, every image, an actual study application, current production source, source responsibility or delivery. OS/standard-library dependencies outside the wheel remain part of the declared host/runtime context; this is not a fully bundled OS or an adversarial sandbox.

## License and historical separation

Every locally installed Pillow wheel/dist-info file is copied raw into `owned/wheel-metadata`, including the full locally installed license texts, `METADATA`, `WHEEL` and `RECORD`, with byte pins in the new inventory. No license excerpt substitutes for the complete text. This also covers the different bundled native dependencies of a Linux wheel.

The historical 66,498-byte local wheel license is retained separately under `vendor/historical-pillow-11.3.0-LICENSE`, SHA256 `2c40a7d8894126ff7a993a752505b915694aafe7a620889ef368acbf54b87144`, and copied into each admission's historical-license context. It supplements the historical runtime record without modifying its freeze. Historical replay outcomes and their original inventory remain untouched and distinct from a new-host result.

`FREEZE.json` binds this bounded tool, exact runtime-support diff, fixed generic inputs/expected evidence, local result, expected platform rejection and source pins. It does not claim that Linux CI has already run.
