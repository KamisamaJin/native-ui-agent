# Predeclared actual source review, pending code

This rubric creates no new native observation items and approves no source now. Apply it to each real task/platform after all-five design admission and before recording any actual source approval. Keep the three existing MUST duties; missing evidence remains unassessed.

1. **Production API / component owner.** Bind `production_api` to actual production files, not placeholders or bridge UI. Verify every exact exported input field, native type, immutable property, initializer/composable/View signature, deployment target, and callback signature against the admitted public API. Inputs are raw facts within the admitted shared integer transport domain. The component owns root/detail/confirmation/receipt state, compares the exposed entity/revision pair on every replacement, preserves valid same-pair state, reconciles root before detail, and emits the exact synchronous callback only from an enabled actual record handler before locking. No fixture value/state ID/test marker/expected output lookup drives behavior. The component has one finite eager main vertical container; fixed root/detail collections expand eagerly to real native Buttons and complete text. No internal scrolling, lazy container, popup, dialog, menu, overlay, network, timer, async task, effect-driven business transition, random value, animation, or forced view identity. All public text remains complete, grows vertically at its declared size, and is reachable through the host's only vertical scroll. Inspect the finite call graph of every custom helper reachable from that main container and every business callback/update handler; enumerate each file and helper. A dynamically selected, unavailable, generated, or unreviewed source branch prevents closed-source approval.

2. **Thin bridge / bridge owner.** Bind `thin_bridge` to the exact bridge bytes used for acquisition. It only converts the schema's raw values into immutable production inputs, applies the existing Android theme where specified, calls the real exported production component, and passes the same `onEvent` directly. No business UI, local selection/receipt state, caller-index behavior, test dispatch shortcut, `.id`/key reset, decision logic, callback transformation, or copied implementation resides in the bridge. Record exact source hashes and the actual symbol passed to the observer. Authored bridge inspection alone is not compiled-provider approval.

3. **Production placement / integration owner.** Bind `production_placement` to real package/product/build configuration and the actual bridge-to-component import/call. The additive Swift file belongs to the existing `AlertToast` product with iOS 14 minimum; Kotlin belongs to the exact documented production package and keeps the stock host/theme. Enumerate the complete finite source roots and custom helper closure. Exclude observer machinery, generated fixtures, private expectations, and test-only replacement UI from production ownership. Confirm the actual later acquisition config binds this same production closure, admitted lock/plan/policy/routes/environment/fixtures/bridge/platform, and explicit host options. The independent intended-platform guard must verify this same config at the mandatory entry before any SDK acquisition. Any changed source or bridge requires fresh source review identity.

For every duty, the later reviewer records the actual file set, byte hashes, cited lines/symbols, finite helper/handler closure, admitted design identity, and pass/block/unassessed decision. Capability compatibility is not source truth. Source review does not stand in for successful dispatch, native capture, native semantics, control-box geometry, pixel samples, or visual assessment. All native assertions and required N/As retain their original denominator cells.
