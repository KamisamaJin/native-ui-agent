# Anonymous alarm preparation

The prospective policy fixes uniform source/report selection and the separate
cause → alarm → matcher → reveal barriers. No actual alarm data was read to
author this policy or the synthetic controls.

`phase_barriers.verify_index(reader, external_ref, 'cause')` requires fifteen
versions, thirty distinct declared contexts, original own-version input seals,
every effective role output and original pair closure. This is a record barrier,
never a product pass. An alarm index additionally requires the verified original
cause barrier and the same actors for each version.

`anonymous_projection.project` permits declared outer metadata omissions and
exact identity/path substitutions only at declared metadata string pointers.
Rendered text, expected or measured values cannot be rewritten. Every other
field, order and status remains unchanged. Unexpected identity disclosure fails
preparation with the original attempt retained.

`alarm_packet.build(reader, spec, anonymous_output, operator_record)` gates all
actual alarm reads on the complete cause barrier, pins every original byte,
copies source/PNGs unchanged, records bounded JSON projections separately, and
seals neutral material. The original selection spec and transformation ledger
remain outside judge inputs. Incomplete preparation retains FAILED.json and
cannot produce a valid sealed task. Root must seal all fifteen specs under the
same prospective policy before dispatching alarm reviews.

The integrated author HOST suite has 38 distinct controls: clock/seal15,
projection8, phase barriers9 and alarm packaging6. Earlier standalone barrier7
and an alarm collection that rediscovered its imported barrier fixture are
retained development records, not additional independent tests. These checks
use synthetic bytes only and do not certify actual product/alarm truth.
