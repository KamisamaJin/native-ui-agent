CI-only verified replay payload disposal

`cleanup.py` removes only the decoded transports and main readonly-restored payload files from one completed, single-use CI replay. It retains ENTRY/RESULT, all compact root receipts and failure history, per-transport DECODED/RESTORED records, RESTORED-MAP, and its own inventory/intent/completion records. It does not import or execute any publication backend, grade products, infer current delivery, open original source keys, or change repository/cold bytes or modes. No actual main package, SDK, actual cache or actual cleanup was run during authoring.

The intended workflow command, after the existing replay exits successfully and before later expensive checks, is:

```sh
python3 -B validation/pooled-forward/publication-replay-cleanup/cleanup.py \
  --replay "$RUNNER_TEMP/pooled-v13-replay"
```

Root owns independent review and workflow integration. No existing workflow, consumer, code pin, original seal or SUT was edited. This helper has no runtime dependency beyond Python's standard library and local POSIX descriptor APIs.

Admission is deliberately specific:

- `GITHUB_ACTIONS` must equal `true`; `GITHUB_WORKSPACE` must be the checkout containing this helper at `validation/pooled-forward/publication-replay-cleanup/cleanup.py`. `RUNNER_TEMP` must be a canonical absolute real directory outside that checkout. The only eligible output is exactly its `pooled-v13-replay` child, with no path aliases or suffix matching.
- This checkout's PUBLICATION.json must match its PUBLICATION.sha256. The manifest is the sole transport authority; no transport IDs or directories are copied into a second manual registry. Code has the original exact eight-role registry and authenticated bytes; original input references are validated as metadata and never opened. Transport IDs are finite, unique ASCII, directories are safe relative paths, and exactly main_transport has restore=true.
- Actual replay ENTRY must name that exact canonical repo manifest and external SHA. RESULT must be the original verified replay kind with the complete declared transport set, readonly payload count, unsupported source/domain boundaries, no SDK execution, no current-source delivery claim, and completed recorded arithmetic. A failed/absent result, FAILURE record or previous cleanup attempt blocks disposal.
- Every cold TRANSPORT and stored-member SHA/size is externally authenticated. Sources must be ordinary readonly files. Every decoded member has exact bytes/hash and readonly mode; decoded INDEX itself has the externally declared index SHA. DECODED/RESTORED provenance and counts must agree. MAP original keys/logical paths/hash/bytes/original mode are projected from that authenticated INDEX. Restored modes must exactly remove write bits from original modes. All mapped files must be present, independently restored with nlink=1 and distinct inodes, with no unlisted files/directories or original-key overlap. No original-key target is read as a fallback.

Before deletion a complete fresh no-follow UID/device/inode/mode/hash namespace inventory and intent are created with exclusive names. The output shape permits declared transport directories only; all other root/transport records must be ordinary owned files and are preserved. Symlinks, FIFOs, other special objects, cross-filesystem generated namespaces and foreign UIDs block deletion. Existing or preempting cleanup receipt names are never overwritten.

Only directory descriptors of the freshly inventoried generated namespace can be fchmod'd. File chmod is absent, including for new receipts: new metadata files are created with mode0444 and written through their creation descriptor. Readonly generated directories may temporarily receive owner access; retained directories regain their original modes after success. Each removal reopens no-follow parents and compares current UID/device/inode/type/mode and regular-file size/mtime with the inventory before descriptor-relative unlink/rmdir. Removal never expands to newly discovered objects or retries after a failure. A partial failure retains its inventory, intent, failure record, remaining objects and any changed generated directory permissions. There is no automatic rollback or resume.

After removal, every preserved compact record and all authenticated repo/cold inputs are rechecked. Shared raw transport aliases may change cold ctime/nlink as a consequence of unlink; their bytes, modes, inode and mtime must remain unchanged. Ordinary read atime may change. CLEANUP.json reports logical namespace bytes, unique-inode allocated bytes recorded before deletion, counts, and explicit non-grading boundaries. These allocation fields do not measure actual filesystem bytes freed, disk quota compliance, historical study cost or treatment benefit. No files under the original repo or cold source are unlinked or chmod'd.

The mechanism requires a quiescent ordinary local POSIX CI namespace after the consumer has exited. Environment variables are trusted platform inputs, not remote platform attestation. Readonly mode is not a same-user sandbox. POSIX unlink is not atomic compare-and-delete against a malicious process replacing a name between the final stat and unlink. Descriptor anchoring and observed identity checks prevent path following and block the tested preemptions; this helper does not claim protection against an adversarial same-user process, malicious filesystem or all possible transient races. Root receipts must already be owner-writable so provenance can be written before permission changes. Directories that cannot be safely inventoried are refused.

Byte verification streams the output files and authenticated cold members, then rechecks cold/source bytes after disposal. It does not duplicate payloads. This adds read I/O and memory for bounded metadata (512MiB per JSON record, at most64 declared transports, directory depth128); it trades some runtime for explicit disposal provenance. It does not solve the restore's earlier disk peak. Actual CI capacity, actual cleanup and subsequent publication checks remain untested here.
