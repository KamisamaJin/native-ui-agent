# Additive modular fixture admission

This pre-run addendum preserves every original protocol, amendment, fixture and
seal byte-for-byte. No candidate implementation, prior validation or business
task was read to prepare it. No SDK, build, native command or device acquisition
has run. These are unbuilt neutral qualification sources, not native results.

The original ABI fixture rendered its view inside the observer bridge. An edit
to that file is a bridge/native-input edit and cannot establish component-source
repair ownership. This addendum moves the same neutral behavior into actual
production source and reduces each observer bridge to input decoding plus a call
to that component. It adds no new business requirement and changes no expected
value, coverage, P/F/U rule, tolerance or performance threshold.

## Installation and subject boundaries

For iOS, add `ios/Sources/AlertToast/NativeQualificationProbe.swift` to the admitted
pinned AlertToast checkout at `Sources/AlertToast/NativeQualificationProbe.swift`.
Use module/product `AlertToast`. Supply `ios/bridge/ObserverBridge.swift` as the
observer bridge; it imports `AlertToast` and calls the public production view.
The component is explicitly available on iOS 14+ because the original fixture
uses LazyVStack/title2. It does not alter the package's deployment target. The
selected native runtime must satisfy that availability; an older runtime is an
admission failure, not a cue to replace the content or upgrade a project.

For Android, add the provided source to the existing module at
`app/src/main/java/org/nativequalification/NativeQualificationProbe.kt`. The main
source accepts `marker: String`, `detail: String`, and `onEvent: (String) -> Unit`.
It imports Compose/Material3 and ordinary platform types; it has no JsonObject or
serialization dependency. The admitted module must already expose compatible
Compose/Material3 to main-source compilation. Use `android/bridge/ObserverBridge.kt`
only as the thin test bridge. JsonObject decoding remains in that test boundary.
No Gradle/plugin/dependency version is guessed or changed by this addendum.

The component responsibility subject is the installed production file, never the
bridge. The native dependency fingerprint must include the actual imported
module/project and bridge separately. Preserve resolved absolute file mappings
and independent before/after digests when materializing. A bridge change can
invalidate native inputs but cannot satisfy a component-source repair task. A
source-review observation citing bridge or generated host lines cannot establish
a claim assigned to the component file. Do not copy the production implementation
back into a substitute test view.

`OWNERSHIP.json` declares only relative installation paths; the operator binds
them to the real admitted checkout before collection. It is not a proof of source
map completeness, dependency closure, build success or source-review correctness.
Never compile both base and repair-control definitions at once: each variant
installs one file at the same production path in a separate isolated checkout.

## Behavior retained from the original fixture

Reuse the original sealed scalar input JSON and five-state `actions.json`.
The normal source retains the same visible text, marker/detail changes, tap
counter, eighteen tall rows, disabled control, last action, 48-unit declared outer
button sizing, spacing and native identifiers. The iOS component owns @State and
the Android component owns remember state. Their per-mounted-view instance token
must remain stable across the caller update and their counter must remain one
after one successful primary activation. The thin bridge does not allocate or
reset that state. Native evidence must establish those facts; source alone does
not establish runtime identity, callback delivery, layout or coverage.

The native instance token is neutral instrumentation of this fixture's state
storage. It does not prove all lifecycle properties of arbitrary SwiftUI/Compose
views. Preserve real app/session/input/event identities as well. The previous
limits on AX/physical touch/style claims continue to apply.

## Independently frozen source-mismatch control

`repair-control/` contains a separately sealed native-source variant for H01/H02.
Its ordinary input, bridge, identifiers, actions, callback names, row count,
environment and original expected facts are unchanged. Its production counter
advances by two for one primary activation. Thus a demonstrated first primary
activation should expose `Tap count: 2` where the independent original oracle
expects `Tap count: 1`; the same count persists after caller replacement. Actual
dispatch and one real `probe.primary` callback must still be independently proven.
The generated task must cite the actual failing state/aspect and production
source, not attribute a callback failure or bridge defect without evidence.

This is an intentionally controlled neutral protocol mismatch, never credit for
finding a business defect or evidence that a product was repaired. The mismatch
variant is outside performance measurement. Do not obtain a passing result by
changing the original expectation, input, route, tolerance or bridge. A claimed
source repair must involve measured production bytes; an unchanged file or a
bridge-only patch cannot close that component-source task. The next default
transition must require actual affected native rechecks and the normal complete
current-code gates before pass/acceptance.

When independently evaluating the repair worker, provide the emitted H01 task,
its minimum cited original native evidence and public skill contract. Do not
give this admission note, the known injected change, an intended patch, or prior
conclusions to the worker. Preserve the worker's actual tool call/response,
measured source diff and fresh recheck evidence. The controlled mismatch's
existence does not itself prove that H01/H02 work.

`ORACLE.json` seals the unchanged expected original facts and the separate control
identity. It supplies no actual native observation. A real blocked/missing native
