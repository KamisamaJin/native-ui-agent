# Independent neutral design and oracle admission

This package compiles the already sealed modular fixture and original five-state
oracle into the documented v12.6 design-contract interface. It was prepared before
any SDK, build, native sample or speed result. Candidate implementation, prior
validation and business tasks were not inspected. The original sealed files are
unchanged. Every scalar expectation comes from the original neutral marker,
detail, counter, controls, callbacks and eighteen rows; none comes from a capture.

`reference.json` is the independent typed source. `contract.json` fixes all rule ×
state cells, with explicit N/A for a callback at a different stimulus or row scans
outside the two full-content states. `bindings.json` contains selectors only.
`actions.json` is byte-for-byte equivalent JSON to the original five-action route.
Compiler-added target observations do not add activation or replace the route.

The cases are `ios-cold` (neutral-A / marker-A), `ios-warm` (neutral-B / marker-B),
and `android` (neutral-A / marker-A). Their exact fixed scalar fixture bytes are
copied under `fixtures/`. All three cases use the same five selected states:
start, after-primary, after-replacement, replacement-full, after-last. Each
generated plan has 104 required native assertions, 170 matrix cells and 66
explicit N/A cells. Both platforms use exact label/control/event assertions.
There are no guessed SwiftUI computed styles or physical-touch claims.

The current lock is `approved-lock.json`; `approval.json` names it explicitly.
`PREPARATION.json` designates the final pure-compiler output directory. Earlier
unsealed schema drafts are retained for provenance and are not native results or
the admission inputs. Native expected values and the five-action route never
changed during that schema preparation.

The marker/detail/counter and primary/last control facts are checked at every
selected state. Token presence/uniqueness is observed but does not compare token
values. All eighteen row labels are checked in each full-content state. Full
content additionally requires the native same-state overlapping intervals and
actual bottom sentinel in the collector/execution receipt; labels alone do not
prove coverage. Primary/last callbacks require successful real native activation
and their exact original intervals. Caller-update quietness uses the documented
caller-update stimulus, including actual input advancement and app/process binding.

## Required unknown and gate meaning

`mounted-component-instance` remains a MUST obligation with an empty route and
explicit U: the documented static expected-value compiler cannot express equality
of an unpredictable mounted token across native states. There is no fabricated
expected UUID and no source-based runtime pass. The generated instance-present/
unique assertions are useful native facts and keep the target in observation;
they have their own `instance-node-observable` route and do not resolve that
relation. Observer app/process/input/event identity is a
different required gate and must still be verified from actual native execution.

This U blocks accepted delivery and all-P component-instance qualification. It
does not by itself invalidate a bounded same-code/same-mandatory-PFU performance
comparison when A and B preserve the identical disclosed U and all actual native
observer identity, source, coverage, environment and resource gates hold. The
comparison must report the U in its denominator and must not describe the whole
qualification as passed. `required-obligations.json` records this distinction.
The route audit is intentionally not all-P; that is an expected open obligation,
not permission to ignore an audit or claim native completeness for that fact.

## Actual review in R0

The required `thin-bridge-decodes-calls` responsibility is a small static source
review: the actual installed thin bridge decodes marker/detail and invokes the
imported production component with the same strings/onEvent, with no local probe
UI/state/control implementation. It adds no UI requirement. The source provider
must bind a real review of the installed file and actual line citations through
the default service's source-review path. Do not prefill observed=true from this
reference or substitute source for runtime behavior. The review remains pending
until that actual observation is bound.

`policy.json` deliberately has no manual visual/pixel atoms because review is a
source responsibility. Its empty atomic catalog is valid and does not satisfy
the source duty. Resolve `evidence_subjects.thin-bridge` to the exact installed
bridge and provide an independent source-review store outside production roots.
The R0 command must route/import that duty automatically using the valid original
package, rather than inventing a dummy image review or extra native run.

## Environment, resources and bounded validity

The approved requested iOS environment is 390pt × 600pt, light, ltr and Dynamic
Type large on the admission-selected iPhone17Pro / iOS26.5. `resources.json` pins
the corresponding standard device-type/runtime identifiers, one owned simulator,
20GiB scratch budget, 5GiB minimum free space, 2s sampling, 86400s resource TTL and
900s native command timeout. The caller supplies a fresh per-arm owned root;
resource TTL does not refresh a capture. Actual installed inventory/toolchain and
native viewport/environment must still be verified; these are specified selections,
not SDK observations. Do not adopt a borrowed resource into the deletion set.

Android is the admitted existing Pixel 5 Paparazzi/layoutlib module, requested
390dp × 600dp, light, ltr and font scale 1.0, with the documented pinned
`paparazzi-float32-screen-config-v1` encoding. The provider-specific 2.75 density /
Float32 / integer-pixel conversion is validated by the shared environment gate;
it is not a product tolerance or a value learned from a screenshot. No arbitrary
epsilon, geometry tolerance or expected font value is introduced here.

`capture_validity_ref` points to a separately fixed rule with a 3600-second maximum
age, fresh-native-fixture reset and all dependencies pinned. Approval applies
only to this controlled deterministic component fixture and route. The source has
no external services; its UUID is recorded session-local identity, not an external
state dependency. Unknown dependencies, current-source/input/environment drift,
insufficient coverage, unresolved observations or an expired package still block
reuse/acceptance. The baseline may ignore this optional new reference while
using identical native expectations and obligation rules. Do not extend the
approval to business apps or to a lifetime inferred from a live pooled device.

## Preparation and remaining integration assumptions

Run `python3 -B prepare.py --output NEW_SUBDIRECTORY` inside this design package.
It only invokes the frozen baseline's documented pure seal/compile/catalog/audit
commands, checks hashes and writes fresh JSON under this directory. It never
passes a native run flag, builds, acquires a device or loads candidate code. It
reproduces the lock and compiles each case; it preserves the original assertions
and retains the expected unresolved mandatory route in its audit output.

The admission owner still must pin/verify the AlertToast revision and installed
production file, Android main/test classpaths and Gradle/JVM/SDK, actual Xcode and
runtime inventory, absolute production/bridge source maps, source-review store,
owner scratch roots, transitive native dependencies and full default-service
configuration. `integration-fragment.json` marks these unresolved placeholders
and is not a runnable config. The schema/compile proof is not build or native
behavior proof. Two platform sources remain unbuilt. No capture or review actuals
are supplied, and no new observer feature is invented to resolve the token U.

The additive repair-handoff interpretation in this package clarifies only the
default service's tool-verifiable handoff record; it does not rewrite original
protocol artifacts or claim a repair happened. `approval.json` pins canonical
lock/policy/routes/environment/resource identities; the external seal pins all
source/compiler products. Hashes do not prove that a design is semantically right.
