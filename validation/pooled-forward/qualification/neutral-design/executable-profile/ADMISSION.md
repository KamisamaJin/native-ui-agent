# Additive supported native execution profile

This is a new pre-run scope approval. The previous neutral-design package, all
its members and its seal remain unchanged. Its static rejection is retained in
`REJECTION-HISTORY.json`. No SDK, build, native/performance sample, candidate
implementation or business task was used to make this correction.

The previous assessment overlooked that a MUST with no route blocks default
acquisition as well as accepted delivery. The prior mounted-child-token MUST
therefore made the proposed qualification profile operationally unrunnable.
Collecting results while simply declaring that mandatory route U would not solve
the default-service admission contradiction.

The mounted-child UUID equality relation was an additional probe diagnostic. The
user's requested capabilities require genuine native app/process/input/event
identity for pooling/evidence safety and preserved observable caller-update
behavior. They do not require proving an arbitrary hidden child UUID relation.
This profile retains that relation as an explicitly advisory U in both
`reference.json` and `overall-capabilities.json`. Its expected relation is not
rewritten, omitted, assigned a fake UUID, or turned into P. This profile makes no
full mounted-child/component-instance acceptance claim.

## What remains mandatory

All 104 original source-backed native assertions, 170 matrix cells and 66
explicit N/A cells per case remain unchanged. The exact five states/actions,
scalar fixture bytes, marker/detail/count values, native controls, all eighteen
full-state row labels, primary/last callback deltas, caller-update quietness,
source review, environments, resources and 3600-second controlled-fixture
validity rule remain fixed. Both A/B arms must use this same profile.

The observable caller-update requirement is still native and mandatory: successful
input advancement 0 to 1 within one capture app/session, exact changed marker and
detail, retained `Tap count: 1`, exact empty callback interval and original bound
native frames. A restarted pair or static source declaration cannot establish it.
Recreating state and resetting the count still fails the original native rule.

The user's native execution envelope is separately explicit in
`native-safety-gates.json`. Fresh iOS acquisitions must have actual new App/test
capture identity even when the simulator is pooled; PID reuse alone is not
sufficient. Each state/action/image/interval must retain matching current
process/session/input/event identity. Android's provider is an actual layoutlib
test/composition session; it is not an Android OS App or physical-touch claim.
Current source/build/bridge/input/environment, full native coverage, valid
original-package reuse and owned-resource lifecycle gates remain mandatory.

Those gates have documented raw native providers and are pending actual
acquisition. They are not impossible static expected-UUID assertions. Missing,
invented or incoherent required raw proof remains U/error and blocks the
requested pool/evidence/speed gate. A component-row P, instance-node presence,
source-review P, simulator UUID or component-profile accepted flag does not
substitute for those raw execution facts. The final qualification report must
show the separate native-gate judgments and evidence.

## Scope and comparison

The supported native route index has nine MUST obligations with available native
routes and one explicitly advisory unavailable token relation. The mandatory
thin-bridge source-review duty remains in the responsibility contract and must be
actually observed/bound in R0. `policy.json` still has no image atoms; source
review is intentional. `overall-capabilities.json` preserves the advisory U so
raw judgments cannot disappear when reporting the supported profile.

The default service may acquire and evaluate this supported profile. Any accepted
status applies to its declared scope; it does not establish the advisory hidden
child relation. The user-requested qualification gate is the conjunction of all
mandatory atomic/source/environment/coverage/resource gates and actual native
safety gates, followed by the same-code/same-coverage exact A/B P/F/U comparison,
no increased mandatory U, and at least 20% lower inclusive collection wall time.
The advisory token U must also remain identically disclosed across arms. No
threshold, tolerance, input, content height, native action or assertion has been
selected from observed results; none exists yet.

`prepare.py` uses only the frozen baseline's documented pure compilers. It checks
zero MUST route gaps and zero unowned assertions while checking that the token
relation is still an unavailable advisory route. It compares the generated native
state/assertion/matrix semantics with the prior sealed plans to establish that
their observable native workload was preserved. That is a schema fact, not a
native pass. Use `approved-lock.json`, `approval.json` and `prepared/` from this
additive package for supported-profile admission; retain the previous package as
the rejected stricter scope.

The pinned AlertToast/module installation, Android main/test classpaths and
Gradle/JVM/SDK, actual iOS runtime/toolchain inventory, exact absolute production/
bridge maps, source-review store, per-arm owner roots and native dependency
completeness still require independent admission. The inherited integration
fragment contains placeholders and is not a runnable config. All sources remain
unbuilt. The previous repair-handoff interpretation is unchanged: a valid
default-generated measured-diff tool receipt is permitted, and native retest
remains required; the receipt is not proof of repair correctness.
