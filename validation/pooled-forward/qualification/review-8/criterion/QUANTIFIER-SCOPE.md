# Additive native quantifier scope clarification

Protocol ID: `native-quantifier-scope-1`.

This is a semantic clarification from the original public native-tool/state
contracts. No implementation, exact native testcase/target values, SDK artifacts,
business task or new result was read for it. All original artifacts and verdict
records remain unchanged; the 104 approved assertions and five states are fixed.

## Scope comes first

Every fact first needs the actual approved state/action, input, process/session,
event and native-evidence binding, including any required established route.
An unbound, stale or wrong-state witness cannot earn a business P/F. A state name
or producer completeness flag alone does not establish those conditions.

Let D be the assertion's declared, actually evidenced native matching domain and
M its matching actual native entities after the existing documented semantic/
control-group rules. `present` means `|M| >= 1`; `unique` for native target
resolution means `|M| == 1`. These predicates are different quantifiers.

A `full_content` assertion refers to the approved bound state's native domain.
Positive cardinality needs complete native matching-domain coverage, including
the required terminal/boundary guards. Complete rendered pixels alone are not a
catalogue of hidden logical UI or proof that every matching native entity was
enumerated. No claim extends to unselected states, other roots, future time,
hidden branches or unsupported nested/off-axis scope.

A `targets`/`target` observation can support an explicitly bounded current native
query scope when that actual query is completely enumerated and coherently bound.
Its local `unique:true` means one match in that query scope, not one match in the
whole logical UI or full state. Keep the query root/frame/time/scope and the
state's `complete:false` visible. A single reported node is not itself proof that
a native query was complete. Ambiguous or unspecified scope retains U.

## Decisive evidence and unknowns

| Native evidence in the valid declared scope | `present` fact | `unique` fact |
| --- | --- | --- |
| At least one genuine matching entity observed; domain incomplete | True | U if only one distinct entity is established |
| At least two genuinely distinct matching entities established | True | False, even before the rest of the domain is complete |
| Complete native matching domain, exactly one entity, no witnessed duplicate | True | True |
| Complete native matching domain, no matching entity ever observed in that scope | False | False |
| No matching witness and incomplete/unproved domain | U | U |

Compare the determined Boolean with the unchanged approved expected Boolean:
agreement is P, contradiction is F, unknown is U. Thus a real observed witness
proves `present:true` and refutes `present:false` without requiring full-domain
completion. A real duplicate refutes `unique:true` and supports `unique:false`
without waiting for a terminal scan. Zero matches proves a negative only when
the relevant native scope is complete; it is not a temporal claim of "never".

One late observed target with an incomplete full-content terminal guard cannot
prove `unique:true` for that full state. It earns U for that cardinality claim,
while its independent `present:true` fact can earn P. Do not require uniqueness
to establish existential presence. Conversely presence does not authorize an
ambiguous activation or settle label/geometry facts that need a resolved target.

Repeated records of the SAME actual entity across scroll frames are not a
duplicate. A duplicate counterexample needs distinct actual native entities in
the same established scope/epoch, with identity/group evidence. Do not count
snapshot rows, reuse of an identifier string, or a permitted semantic/control
wrapper collapse as two entities. Do not deduplicate two actual entities merely
because their selector/label is equal. If one-versus-two identity is unresolved,
positive uniqueness is U. All contradictory bound evidence remains visible;
one convenient locally unique frame cannot erase a real duplicate counterexample.

The existing action/callback method gates are unchanged. A locally unique native
dispatch target does not certify global uniqueness, and a presence P does not
turn an unexecuted/blocked action or empty unestablished callback interval into P.

## Existing late-presence record

Under the task's stated premises of successful complete coverage and genuine
coherent late presence witnesses, `present:true` is decisive P. The additional
completeness condition for positive full-domain uniqueness supplies no reason to
withhold that existential fact or reinterpret it as a uniqueness question.

This is a conclusion under those stated premises, not a regrade of unread native
evidence. The original 100P/4U record remains exactly as recorded. It is not
overwritten, relabeled or used to invent new expected values/coverage. Any future
tool recomputation must be a separate versioned artifact retaining the originals;
none is performed here. Both comparison arms must use the same verifier semantics,
mandatory denominator and scope accounting. No design threshold, tolerance,
fixture, action, state or expected Boolean changes.

The public contracts support this boundary: real matching native facts can be
established from bound joint frames; unseen targets cannot establish absence
without complete scope; target-only evidence is not full-content evidence;
ambiguous native matches cannot justify a first-match activation. This clarification
does not introduce a new observer feature or a whole-logical-UI uniqueness claim.
