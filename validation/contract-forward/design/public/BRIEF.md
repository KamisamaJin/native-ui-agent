# Workshop enrollment card

Build one production native component inside each pinned host library/application: SwiftUI in AlertToast and Compose in Reply. This is a small team-training enrollment form, with its own local draft and confirmation state. Integrate no networking, navigation, persistence, or asynchronous loading. The observer bridge must render the actual production card.

The caller supplies a catalog with a title, explanatory detail, ordered courses, remote discount, one-time in-person fee, and per-person workbook price, all integer cents. Each course has stable ID, title, detail, seat price, capacity, in-person availability and workbook availability. Supplied prices are nonnegative; seat price is at least the remote discount. The fixed seat bundles are 1, 3 and 6. Capacity means remaining seats, not a counter to decrement locally.

On first appearance select the first course with capacity at least 1, Remote, 1 seat, no workbook. A zero-capacity course remains visible and disabled. Course titles and descriptions may be long. Show every course, mode and seat choice as its own visible native option. Do not use pop-up menus or horizontally scrolling selectors. Stable identities appear below. Unavailable options remain visible and disabled. Selected options carry native selected state, including when disabled after reservation.

In person is available only if the selected course supports it. Remote is available whenever a course is selected. Workbooks are available only for an in-person course that supports them. Switching to Remote resets workbooks to false; selecting a course without in-person support resets mode to Remote and workbooks to false. If a new selected course cannot accommodate the current seat bundle, choose the largest of 1/3/6 that fits. Changing any choice does not dispatch a callback.

Total cents = seats × (course seat price − remote discount when Remote) + seats × workbook price when selected + in-person fee when In person. Format exactly `Total $<dollars>.<two digits> · <n> seat[s] · Remote|In person · Workbooks|No workbooks`; singular only for 1. A missing selection uses zero seats and zero total. Show `Choose options, then reserve.` while valid and unconfirmed; `No courses available.` if none are available.

`Reserve seats` is enabled precisely when a valid course is selected and the draft is unconfirmed. A successful reservation emits exactly one typed reservation callback with course ID, mode, seats and workbook flag. It then shows `Reserved <n> seat[s] for <course title>.` All selectors and Reserve become disabled, retaining the selected values and total. An always-visible `Edit selection` button is enabled only while confirmed. Editing restores the same draft and emits nothing. Disabled actions do not dispatch. Tests of quiet callback behavior require a proven successful requested dispatch; an attempted disabled activation is U for callback behavior.

When the caller replaces the catalog on the same component instance, clear confirmation; preserve the selected course by ID only while it still exists and capacity >=1, otherwise choose the first available course in the new caller order. Preserve mode if supported, otherwise Remote. Preserve a valid seat bundle, otherwise choose the largest fitting bundle. Reset unavailable workbooks. If no course is available, select none, use Remote/0/no workbook, disable all selectors and Reserve, keep Edit disabled, and show the empty status. Emit nothing on replacement. If a later catalog becomes available, choose the first available course and 1 seat. Catalog replacement is ordinary production input, not a fixture-specific API.

Structure: title, caller detail, Courses section with title and detail for every course, Attendance section, Seats section, workbook toggle button, separate total surface, status, Reserve, Edit. Use vertical stacking and wrapping so narrow and large-text content remains reachable in the parent's single vertical scroller. Do not add a nested vertical scroller. Preserve caller direction. Full text must wrap; ellipsis and line limits are prohibited on caller title/detail/course copy, total and action labels. Short choices may wrap into multiple rows.

Visual tokens: card corner radius 16; internal padding 16; major section gap 20; option gap 8; option padding 12; border 1. Values use pt in SwiftUI and dp in Compose. Title 22 semibold, body 16 regular, section labels 14 semibold, option title 16 semibold, total 18 semibold, action text 16 semibold; use scalable native fonts (Compose sp). Title ink light #172B3A / dark #F1F5F9; body light #425466 / dark #CBD5E1; surface light #FFFFFF / dark #182635; selected fill light #E7F2F8 / dark #233E52; accent light #155E83 / dark #8ACBEE; selected border accent. Disabled options use native disabled affordance while readable. Reserve is a filled accent action with contrasting text; Edit is secondary. Native action accessibility/semantic boxes must be at least 44pt iOS or 48dp Android in height. No exact width or internal-padding claim may be inferred from a text AX box.

Stable identities: `enroll.title`, `.detail`, `.course.<id>`, `.mode.remote`, `.mode.onsite`, `.seats.1`, `.seats.3`, `.seats.6`, `.workbook`, `.total`, `.status`, `.reserve`, `.edit`. Identity the actual option/button rather than a duplicated hidden proxy. SwiftUI use accessibilityIdentifier and native selected traits; Compose use testTag on the actual semantic control and selected semantics. Preserve distinct semantic text nodes for title/detail/total/status. Do not merge the whole card into one accessibility element.

Public cases: P1 normal/light/LTR with reservation and live catalog replacement; P2 long content/300-width/dark/RTL/large text with a disabled mode, capacity reconciliation, confirmation, edit and replacement. Each includes two actual caller models. One separate hidden case is held until both final implementations are sealed. No planted defects. The public wireframes freeze structure, wrapping intent and tokens; native font baselines are not pixel-exact references.

Measurement policy: exact strings, booleans, event arrays and ARGB colors; Android font size near 22sp with 0.05sp tolerance for serialization only, not a visual size tolerance. Geometry is a native semantic/control box lower bound, no floating equality, and a box must be fully visible. Public iOS generic computed font/color/ellipsis measurements remain U. No generic layout allocation is claimed. Manual visual row checks only complete Reserve-label visibility using actual state screenshots, with screenshot hashes and indices; it cannot establish computed iOS font/color. Zero observed overflow is not inferred from text width. A U remains U if evidence is missing. The design has 24 atomic rule families and retains every state/platform cell, including independent N/A.

Selected acceptance scope: the 24 families score heading/detail/total/status text; selected/enabled course, attendance, seat and workbook facts; Reserve/Edit enablement; gated activation/replacement callbacks; native title size/color where supported; detail ellipsis where supported; Reserve semantic/control minimum height; and actual Reserve-label visibility. The prose visual tokens for corner radius, internal padding, section/option gaps, border thickness, non-title fonts/colors and surface fills guide implementation but are outside this selected numerical denominator. Their wireframes are normative visual intent, not an assertion that those unmeasured values passed. Course-description clipping and whole-card visual similarity also remain outside the selected denominator. API/input checks have their own separate rows.
