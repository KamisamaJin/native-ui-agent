# 三任务前瞻盲测：未证明 v7 质量优势

本轮完成三个全新复杂 UI 任务、六份双端实现、132 次计划原生采集。先冻结通用工具，再独立固定设计和验收；全部成员逐阶段封存，原始四阶段评分及单独共享修正复核均封存后才揭盲。没有向产品注入缺陷。结论仍是：**未证明 v7 提升真实缺陷检出、修复率、覆盖或端到端成本。** 原始 Android 验收集成失败、评审分歧和所有失败尝试均保留。

## 这次实际比较了什么

对照为 `249aae5c` 的 v6.1，处理组为预先冻结的 v7。两组已有独立设计契约、预期来源校验、生成断言、动态原生定位和视觉审查。这不是 Skill 与无 Skill 的比较。六份实现均为不同源码；逐文件摘要和新版实际使用的几何证据见 [implementation-comparison.json](implementation-comparison.json)。

| 新任务 | 主要复杂性 | 生产模块 |
|---|---|---|
| T1 ExpeditionPackPanel | 多选与资格联动、详情展开、调用方替换、受限提交 | AlertToast / Reply |
| T2 BroadcastCueMixerPanel | 多通道步进、锁定/静音、负载阈值、应用与重置 | AlertToast / Reply |
| T3 CollectionConditionReviewPanel | 队列导航、分类与原因、只读项、持久决策与完成 | AlertToast / Reply |

每项包含正常、窄屏/深色/大字公开输入及独立保留输入；每份初次 528 个、最终 792 个选定评分单元。三个任务对才是独立开发样本，不能把平台、状态、评分行或命令数当成更多试验。22 个断言族没有覆盖完整 brief。

五个簇主要来自两种重复机制：iOS 调用方替换后保留旧内部选择，以及默认禁用绘制进一步淡化指定配色。它们不是五种独立失效机制。两组修复了主评分已确认的全部表现，不能据此推断原先自测报告已完整检出，更不能把最终零 F 称为完整验收通过。

v7 的较低严格检出信用，主要来自原始人工发现的预期/单位与冻结描述符不一致。例如同一组配色问题被写为角色字典，而冻结验收使用文字描述。不能在看过答案后补齐描述符，也不能据此认定模型完全没看见该问题。原始计划、发现、修改、匹配和分数均保留。

## 误报：保留三种口径，不能制造精确答案

冻结身份账本的合并 TP/FP/U 为 v6 **45/8/17**、v7 **32/17/6**，拒绝比例分别 15.09% / 34.69%。其中 FP 含预期或单位身份不符，**不能直接当成真实产品误报率**。

原始独立验收者另外给出的产品判断，合并为 v6 **45 TP / 0 labelled FP / 10 eligible U**，另有 15 个定性未知；v7 **32 TP / 2 labelled FP / 15 eligible U**，另有 6 个定性未知。对应条件比例为 0% / 5.88%，但两条 labelled FP 与原图证据冲突：两组 common 截图都显示 D0 禁用填充偏色、FINAL 恢复 brief 指定颜色，原视觉验收却一直判 P。该只读审计没有改写任何分数，见 [原始像素分歧](GRADER-DISAGREEMENTS.md)。

因此目前**客观裁决的真实产品误报率不可确定**；没有完整真阴性集合，经典 FPR 也为 N/A。不能选择严格账本、定性 AI 标签或事后像素审计中最有利的一种来宣布优胜。完整逐任务判定、未知范围和来源摘要见 [TABLES.md](TABLES.md)及 [review-product-summary.json](review-product-summary.json)。

## Android 共享集成失败与单独修正

原始独立 oracle 将真实 Compose `Ltr` 与契约 `ltr` 直接比较，导致 Android 适用项全部 U。三个独立验收者各自指出问题；原始 62 个合成控制都使用契约拼写，因此未发现真实线格式不兼容。主试验的双端覆盖结论受到这项共享失败限制。

新增 provider 显式的已知枚举适配器 [tools/native_environment.py](../../tools/native_environment.py)，拒绝未知值，不猜测任意平台字符串。新增回归覆盖真实原生线格式。原始评分、产品、输入、预期和容差不变；另封存修复，在原始四阶段全部完成之后、揭盲之前，使用相同原生记录进行独立匿名复核，无新增 SDK 或产品修复。

| 共享修正后的最终严格评分 | v6 | v7 |
|---|---:|---:|
| P / F / U / N/A | 1894 / 36 / 224 / 222 | 1894 / 36 / 224 / 222 |
| 未评估 / 适用 | 224/2154，10.40% | 224/2154，10.40% |

这是事后共享基础设施收益，**不是 v7 收益**，也不能替换失败的原始主结果。新增 F 全部保留；覆盖增加不意味着产品质量提高。

新增 Android 画布 F 的责任分类存在评审分歧：T1 将 v7 的 12 个 D0 / 18 个 FINAL 表现列为宿主与组件责任未确定；T2 将两组同类 12 / 18 个表现列为采集宿主配色问题；T3 将 v6 的 12 / 18 个表现列为组件未实现画布角色的产品簇。通用宿主确实有固定背景，三个 brief 均规定画布颜色，但公开 API/brief 没有统一明确背景由哪层绘制。所有 F、原因判断和证据原样保留，未事后统一标签。

因此，补充评分中 v6 产品簇修复 5/6、v7 5/5，是依赖这些独立原因标签的结果，**不足以证明新版质量优势**。它暴露了验收责任边界仍不稳定。完整原始/修正表见 [SHARED-INFRASTRUCTURE.md](SHARED-INFRASTRUCTURE.md)，原因分区见 [quality-breakdown.json](quality-breakdown.json)。

## 数值边界与新未评估项是否解决

v7 使用实际 Compose 整数像素尺寸、原生 density 和位置样本做有理数运算；iOS 使用直接 CGRect 尺寸，避免再次通过端点相减引入误差。保留 provider、原始样本、选择器和帧来源。没有加全局 epsilon、扩大设计容差或把边界数值直接吸附到预期。畸形新精度包记 U；缺包走明确标记的旧计算路径。成功派发回调的前置条件保持不变。

98 项工具检查及独立中性原生验证在新任务设计前完成并冻结。中性 iOS 本身返回过 `51.999999999999986` 和滚动中变化的尺寸，原始严格 F 继续保留；该实现只消除对已采集原生样本继续计算时额外引入的误差。它不提供 SwiftUI 计算字体/颜色树，也不证明实际 padding、变换后绘制或物理命中区域。

实际同源码 v6/v7 采集配对 3024 个单元，原始与共享修正 oracle 下都没有新增证据、证据丢失或 P/F 冲突。原始 U 为 1660→1660，共享修正为 300→300。额外同帧离线比较的 296 个适用几何断言全部 P→P；数值读数/证明可以不同，但没有判定收益。没有为让新工具获胜而再选择任务、注入缺陷或调整阈值。

## 端到端成本与为什么仍无优势

各任务实现→自身最终原始证据封存：v6 **74.74 / 77.06 / 82.23 分钟**，v7 **74.72 / 77.19 / 81.70 分钟**；三任务均值只差约 8.60 秒。两组自身原生命令资源工时合计分别 51.98 / 52.06 分钟，不能将重叠资源工时直接相加当作经过时间。共享 Mac、缓存、固定资源槽、任务次序及全员屏障使提速因果归因不成立。

六组完整公开证据封存共 94.29 分钟；首次实现至揭盲 175.79 分钟，预注册至揭盲 224.88 分钟。独立审计与配对额外原生命令资源工时 177.05 分钟。单独共享修正复核三位验收者实际阶段为 598.08 / 384.78 / 498.43 秒，无新增原生采集。没有 token 或账单记录，费用记 N/A。发布整理与 CI 不在上述揭盲终点内。

132 次计划命令全部 exit 0，包含 6331 个 iOS / 4415 个 Android 快照记录；命令成功不表示验收通过。iOS 原生测试命令资源时间约 263.43 分钟，构建/验证约 5.85 分钟，表明本轮主要采集成本已在原生观测与滚动采样，继续只优化编译缓存收益有限。Android 原生测试内部细分计时没有记录，不能估算填补。详细成本见 [costs.json](costs.json)与 [observation-costs.json](observation-costs.json)。

本轮未体现优势有明确边界：v7 新增能力主要修正计量链和流程纪律，主要自然缺陷却是生命周期与视觉语义，两组原有工具都能处理；新任务没有实际触发数值边界上的判定差异；严格发现格式和独立视觉验收仍不可靠；iOS 计算样式仍缺公开证据。将任务扩为三对增加了暴露问题的机会，没有使这些瓶颈自动消失。

下一轮应先独立冻结画布/宿主的责任契约，并用真实线格式验证整个评分链；将颜色角色等验收方面拆为来源明确的原子断言，保留有效像素采样与计算属性的区别；对有争议的产品判断增加可靠外部裁决。采集优化应以目标覆盖证据驱动停止条件，同时验证未丢状态，而非只少截图。这些是本轮之后的工作方向，没有在看到结果后改进并重算本轮。
