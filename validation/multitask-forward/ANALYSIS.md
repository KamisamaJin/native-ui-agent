# 上轮未体现质量优势的原因

1. v6两组的502个公开适用预期都正确，且没有确认自然产品缺陷。来源校验的负例拒绝证明机制生效，但没有真实缺陷分母可用来估计检出、误报或修复优势。三个原始高度F仅约0.00006dp，不能当作三个产品bug。
2. Android把整数原生尺寸加到Float位置，再把两端各自除以density并序列化，Python再相减。跨滚动帧的坐标舍入使一个不变尺寸出现48dp上下的值；v6更多帧导致三项混合P/F变U。这是测量链和聚合造成的问题，并非三个确认的定位失败。
3. iOS计算文字样式缺口与禁用刺激后的回调前提仍在。公开AX不能给出通用SwiftUI计算字号/颜色，未成功派发的空回调不能证明业务正确；本轮不能靠改变这些分母获得优势。
4. 单个需求、一次随机实现、共享机器/缓存的−6.13%命令时间差不足以证明交付提速。薄组件宿主也不等于完整旧App页面/导航/后端质量。
5. 首轮存在26.5秒提前采集偏差。自然流程本应先封存再启动SDK，不能只在事后核对时间。新版试验将全体候选的屏障变为启动前条件，保留一次被拒绝的提前启动控制。

本轮改进记录实际原生尺寸/位置/density，用有理数计算几何并保留可回溯样本，避免新增导出运算误差。不把测量分辨率混作设计容差，不在看到新需求后调数值、选任务或改评分。所有修复先经过中性原生验证和独立上下文，再冻结工具和全新三任务设计。旧评分和失败记录不改写。
