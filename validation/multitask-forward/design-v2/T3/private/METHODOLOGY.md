# Independent design-v2 oracle methodology

This task was chosen from its realistic business needs after a preimplementation review rejected only the original cohort's shared visual skeleton. No production candidate had been written and no candidate SDK command/render occurred. The original design/ directory was preserved unchanged. The designer read only the frozen candidate-v7 supported schema, its own prior generic oracle and the explicitly authorized preimplementation review record. No probe, assignment, prior-trial output, implementation or suspected defect was used.

Each task independently fixes 22 requirements across 6 selected states × P1/P2/H1 × iOS/Android =792 denominator cells, including every explicit N/A reason. Different arrangements use different targets and public API models. Generic oracle_common.py does not assume two equal-width choices, any fixed control arrangement or identical action indices; it reads each approved typed plan. Its bytes are retained to preserve copied T1's original valid seal. v2_oracle_controls.py creates synthetic evidence for arbitrary approved targets, including channel steppers and master/detail review controls. Synthetic corruption never touches production code. No SDK is required for these controls.

The exact separately approved canonical design-lock digest is in approval.json. The grader always reads compiled/<case>/<platform>/plan.json from this sealed design root and verifies its exact derivation against the lock and digest using frozen candidate-v7 native_checks/design_contract. It never reads a builder plan. CLI seal/compile commands and their exact equality to grader/common inputs are preserved in compiler-audit. Geometry precision and style scope are fixed publicly before native feedback. Unsupported applicable style rows remain U, including generic computed SwiftUI font/color/weight/ellipsis. Visual judgments never substitute for those native rows.

## Grader and storage contract

Import private/grader.py and call grade(case, platform, observation_path, root=None, manual=None, source_root=None, api_review=None). case is P1/P2/H1; platform is ios/android. Normal corpus path is R/common-corpora/<Tn>/<source-a|source-b>/<d0|final>/<ios|android>/<case>/observation.json. root is the directory resolving the original screenshot/manual evidence paths, normally observation_path.parent; it is not the design directory. All output evidence inside R is relocatable relative to R. The grader returns rows, counts, input_checks, api_checks and native_report without writing output. Store native_report as native-base.json, full return as grade.json and original manual record as manual.json beneath R/evaluation/<D0|FINAL>/<Tn>/<alias>/<case>/<platform>/.

Rows contain unique id,case,platform,state,requirement,aspect,class,status P/F/U/N/A,expected,unit,op,tolerance,actual,snapshot_indices,reason,evidence. Classes are business_current,business_transition,geometry,native_style,visual. API/input validity stays separate and never enlarges acceptance counts. Missing or rejected native evidence leaves applicable rows in denominator as U. Wrong caller fixture or actual native environment is a separate input F and withholds applicable acceptance passes.

manual accepts a path or native_checks object: observation_sha256 and decisions with exact <state>/<requirement> id, status passed/failed, method visual, original snapshot_indices, reason and evidence path/sha256 for original state PNG files relative to root. Grader checks actual PNG signatures; frozen native checker binds exact observation/state/epoch/hash. Full-layout loaded/replaced passes require complete original state coverage. Target-state review is limited to captured regions.

source_root is the overall dual-platform checkout or platform checkout. Source-symbol existence is only a lexical precheck. Optional api_review must state source_sha256,reviewer,reason,status P/F and optional findings to establish a separate reviewed API disposition. No handwritten observation flags are accepted as API proof.

match_claims(grade, claims) accepts a list or {claims:[...]}; each claim requires exact case/platform/state/requirement, matching expected/unit, status F/P/U. A defect claim uses F. Returned P means supported scoped claim, F means wrong scope/expectation/unit or contradicted claim, U preserves uncertainty. compare_pair(a,b) compares only business_current/business_transition/geometry/native_style on the exact same full native denominator; visual and separate input/API checks are excluded.

H1 changes ordinary public input combinations, seed state and caller replacement only. It introduces no business rule, selector surprise or deliberate defect. Disabled routes explicitly allow_disabled; a blocked attempt cannot establish empty callback behavior and remains U even while independent current-state facts can pass.
