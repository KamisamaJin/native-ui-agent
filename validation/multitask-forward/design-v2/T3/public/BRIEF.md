## Composition and business workflow

This is a master/detail condition-review workflow. Render a vertical three-object inspection queue in caller order, then an inspector for the selected object. Every queue row shows exact accessible label `TITLE, Pending`, `TITLE, Stable` or `TITLE, Needs care`; the active row exposes selected state. Selecting a row changes focus and preserves all object decisions. The inspector shows the focused title, material, long inspectionNote, a Read only indication when editable=false, then vertically stacked Stable and Needs care choices. A Stable decision clears reason. A Needs care decision retains an existing reason only if that object was already care, otherwise starts with no reason. While care is selected, reveal a Care category group with Surface and Structure choices. Only a focused editable care object may change its reason. Read-only records disable classification/reason controls, never queue navigation. Current object seed statuses are pending/stable/care; a care seed may intentionally have an empty reason and needs validation. Ignore a reason unless status is care. Unknown focusID falls back to first object. A complete decision is stable, or care with surface/structure reason. Summary counts all complete objects and all care records: `N of TOTAL reviewed • M follow-up[s]` (singular only when M=1). Submission requires every required object complete; optional pending objects are allowed and included in callback. Validation priority: Choose a care category if any required care record lacks a valid reason; otherwise `N required decision[s] remaining` if any required record is incomplete; otherwise Ready to submit. Confirmation sends all actual decisions without changing focus. Replacement request.id restores all decisions from the new seed and sets focus from the new caller focusID. No item steppers or optional upgrade control are used.

All supplied long note paragraphs appear in order below the primary action under Review notes. Assign the heading identifier `condition.notes`. Title and context use caller values. Primary label is `Submit review`. Native controls expose exact unique identities from bindings.json, real disabled state and selected semantics for selected modes, muted controls, active queue rows and classification/reason choices. Native selected trait: SwiftUI accessibility selected trait; Compose selectable semantics. Keep dedicated text nodes for title, current level/summary, focused title and inspection note where present. Do not nest a native OnClick inside another OnClick control.
