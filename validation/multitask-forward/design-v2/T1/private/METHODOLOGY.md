# Independent oracle methodology

The design context received only the task charter and frozen tool schema. It did not read assignments/private, earlier trials, generic probes, candidates, screenshots or reported bugs. Three unrelated domains were selected before production implementation. H1 changes ordinary seed/input and caller replacement under the same public rules and adds no requirement. No deliberate production defects or mutation testing are used.

The complete acceptance table is generated from independently authored typed expectations and includes every case × platform × state × rule. The SDK-free grader imports the frozen candidate-v7 native evaluator and reads only the exact precompiled approved plan and canonical lock digest from this sealed design. Implementation plans are never read. The oracle tests use synthetic SDK-free observation controls, never production mutations. Unsupported native observations stay U. Manual visual evidence must identify original state PNGs with matching SHA256 and exact observation binding. Pair comparison includes business_current, business_transition, geometry and native_style only, with P/F/U/N/A denominator shown; visual decisions and input/API integrity stay separate. Claim matching requires exact case/platform/state/requirement and expected/unit identity. A claim of a defect requires oracle F; P cannot substantiate a defect, and U remains uncertain.


## Grader calling and corpus plumbing

Import `private/grader.py` and call `grade(case, platform, observation_path, root=None, manual=None, source_root=None, api_review=None)`. `case` is exactly P1/P2/H1; platform is exactly ios/android. `observation_path` is an original common corpus observation, normally `R/common-corpora/<Tn>/<source-a|source-b>/<d0|final>/<ios|android>/<P1|P2|H1>/observation.json`. `root` is the directory against which snapshot screenshot paths and manual evidence paths are resolved, normally `observation_path.parent`; it is not the task design root. All grader outputs cite evidence relative to R when stored inside R. There is no expectation of a fixed candidate source alias in grading.

`manual` accepts an object or JSON path in frozen native_checks format: observation_sha256 plus decisions with id `<state>/<rule>`, status passed/failed, method visual, original snapshot_indices, reason, and evidence array of path/sha256 for every original state PNG. Evidence paths are relative to root. Native checks bind those decisions to the unchanged observation and state epoch. Grade returns rows, counts, input_checks, api_checks and native_report; write native_report to native-base.json, the full returned object to grade.json, and preserve manual.json unchanged in `R/evaluation/<D0|FINAL>/<Tn>/<alias>/<case>/<platform>/`. No automatic write occurs.

`source_root` may be the overall dual-platform checkout or a platform project directory. Optional api_review is a source-bound object/path with source_sha256, reviewer, reason, status P/F and optional findings; simple symbol existence is a lexical precheck and never a complete API proof. API/current input checks are reported separately and cannot inflate native acceptance counts.

`match_claims(grade, claims)` accepts a list or {claims:[...]}. Each claim must state exact case, platform, state, requirement, expected, unit and status F/P/U. A defect claim uses F. Return P means that precise scoped claim is supported; F means wrong expectation/unit/scope or a contradicted claim; U preserves unavailable evidence. `compare_pair(a,b)` accepts grade objects with equal full native denominators, possibly combined across cases/platforms, and excludes visual rows and separate input/API checks.
