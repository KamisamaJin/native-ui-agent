# 本轮验证的含义与边界

本轮比较 `249aae5c` 的 v6 与冻结后的 v7。两组都已经使用独立设计契约、来源校验、生成断言及原生组件宿主；不是“有 Skill 对完全没有 Skill”。v7 的新增处理是原生几何数值链和封存屏障，不能把两组共享的能力算成 v7 增益。

三个全新任务分别是户外装备组合面板、广播多通道混音面板、馆藏逐条状况审核面板。任务同时包含多状态业务、原有选择的替换、受限/禁用操作、长内容和窄屏/深色/大字设置。设计者在实现前固定公开需求、参考图、接口、设计契约、22 个断言族以及隐藏输入；六份实现由独立最小上下文产生。未向任何候选注入产品缺陷。最初的任务提案因交互类型过于相近，在任何实现和产品 SDK 采集之前整体退回，原提案和时间证据保留。

同一任务的两组收到同样公开设计、预算和默认模型设置。各有一次实现、一次只读自测审查、一次修复，允许提前完成。全部六份实现封存后才启动初次采集；全部六组初次采集和断言封存后才开始审查；全部审查封存后才允许修复；全部最终源代码封存后才启动最终采集；全部公开最终证据封存后才展开隐藏输入。原生启动包装器在调用 SDK 前核查上游完整成员、文件摘要和阶段，拒绝提前启动。它是可审计流程屏障，不是防恶意越权的安全沙箱。

独立验收者先分别封存初次和最终评分，再读取实现者的原始发现做匹配，最后处理同源采集对照。每个阶段必须三个任务全部封存才允许下一阶段交付；之后才揭示分组。验收者可以读明确交付的匿名源码、原生记录和原图，不能读分组、实现者历史、其他任务或未来阶段。独立 AI 验收不是人工标注金标准。

每份初次实现有 528 个固定评分单元，最终有 792 个，其中包含原始不适用项。一个评分单元是任务/案例/平台/状态/要求，不是独立实验。三个任务才是三个任务对，不能把状态、平台、数千条评分或 132 次原生命令宣称为更多独立开发试验。22 个断言族没有覆盖完整 brief 的每个字体、间距和业务细节；各验收 summary 的 unasserted_scope 明列未进入评分的要求。

保留严格 P/F/U/N/A 及失败原因分类。数值 F 不自动等于产品缺陷；只有原始原生数据、截图、独立设计与源码证据能支持的自然产品矛盾才进入产品缺陷分母。测量误差、观测失败与原因不明分别保留。簇计数合并同一原因在多个状态的表现，簇修复要求其全部已确认表现通过，不能只挑一张好图。

检出指标只使用实现者封存时写出的原始机器/人工发现。描述符必须包含确切案例、平台、状态、要求、预期和单位；不能看过独立答案后补齐。未映射的宽泛印象保留未知，不能据此认定“模型完全没看见”，也不能补记检出。显式成功观察不属于失败报警分母；与机器失败重复的人工描述不重复计数。FP/(TP+FP) 是可判定报警的条件误报比例；没有完整 TN 标注，经典 FPR 为 N/A。未知项及其误报上下界单列。分母为零时为 N/A。

Android 使用真实 Gradle/Paparazzi/Compose JVM 组件测试，不是 Android 模拟器或物理设备。iOS 使用实际 Simulator/XCTest。两端都通过明确的公共组件 API 与语义定位接入，这是新增组件工程测试，不证明模糊业务描述能在任意无标识旧 App 中零改动定位。计算 SwiftUI 字号/颜色等公开观测缺口继续保留 U；图片目测不会变成精确数值测量。

v7 从 Android 原生整数尺寸、实际 density 和位置样本进行有理数运算，避免导出再相减引入的额外误差；iOS 优先保留 CGRect 直接尺寸。没有放宽设计容差或加全局 epsilon。原生浮点采样本身的精度、真实布局矛盾、变换后的绘制边界、祖先裁剪和物理命中区域不在此数值保证之内。

全部初次独立评分封存后发现，独立验收器把 Compose 的 `Ltr` 与契约 `ltr` 直接比较，导致 Android 全部适用项被完整性前提压成 U。这是共享验收集成失败。原始四阶段评分保持不变；另封存通用已知枚举适配及回归检查，再在全部原始阶段完成后由相同匿名验收者单独复核。它使用原始数据、无新 SDK 或产品修复，在揭示分组前封存，并以“事后共享修正”单列。此项修复不能计入 v7 收益。

主要成本从每份实现开始一直计到自己的最终公开证据封存，包含中间等待、屏障、采集与修复。另报六组完整公开封存、独立验收、同源诊断、共享修正及完整试验到揭示的耗时。原生命令和模型阶段的和是资源工时，重叠执行时不能当作经过时间。共享 Mac、固定资源槽、任务顺序和缓存使速度因果结论不成立；没有实际 token/账单记录就不估算费用。
